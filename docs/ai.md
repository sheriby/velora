# AI 使用指南

Velora 的 AI 围绕 Markdown 的阅读、写作和跨文档整理工作。助手由你主动打开，生成的修改先供审阅，接受之后才进入正文。

## 配置模型

打开「偏好设置 → AI」，添加连接并填写：

| 设置 | 填写内容 |
|---|---|
| 名称 | 自己容易辨认的连接名称 |
| 服务地址 | 模型服务商的 API 地址，或本地兼容服务地址 |
| 模型 | 服务商提供的模型 ID |
| API Key | 服务商的 Key；无需鉴权的本地服务可留空 |
| 协议 | Chat Completions、Responses 或 Anthropic Messages |
| 上下文预算 | 模型支持的上下文 token 数量 |

可配置多条连接，选定默认连接后点击偏好设置底部的「保存」。连接测试会在隔离的空资料集里实际调用一次文档工具，不读取你的工作区正文；成功说明基础请求和工具调用都可以工作。修改输入后可以重新测试。

以 DeepSeek 官方为例：服务地址填写 `https://api.deepseek.com`，协议选择 Chat Completions，模型填写 `deepseek-flash`，API Key 使用官方 Key。

配置文件是应用配置目录中的 `ai.json`。macOS 路径为：

```text
~/Library/Application Support/app.velora.velora/ai.json
```

也可以直接编辑它，Key 存在 `endpoints[].api_key`，不需要系统钥匙串授权。完整连接示例：

```json
{
  "default_endpoint": "deepseek",
  "endpoints": [
    {
      "id": "deepseek",
      "name": "DeepSeek",
      "protocol": "chat-completions",
      "base_url": "https://api.deepseek.com",
      "model": "deepseek-flash",
      "api_key": "填写你的 API Key",
      "context_tokens": 64000
    }
  ]
}
```

每次发送任务都会重新读取连接配置。新任务使用默认连接，也可以点击指令栏上的模型名称切换。

## 从选区开始

1. 在正文中选中文字，点击浮动工具栏上的 AI。
2. 在指令栏选择润色、缩短、翻译或解释，也可以直接输入要求；其余内置操作和自定义指令在 `⋯ → 更多 AI…`。
3. 翻译时填写目标语言，再发送。
4. 直接在正文区域查看排版后的建议，用审阅栏逐处接受或拒绝。

正文右键也提供常用 AI 指令。有选区时处理选区；没有选区时可询问 AI、总结本文或从当前插入位置续写。需要选区的任务不会自动扩大到整篇文档。

`⌘J`／`Ctrl+J` 可以打开或收起助手，命令面板中也可以搜索 AI。相关快捷键可以在偏好设置中修改。

任务固定到发起时的文档和选区。切换标签或分屏后，它仍然处理原任务；正文继续变化时，接受修改前会重新校验，不能把旧建议覆盖到新内容上。

## 指令与正文各司其职

入口是一条就近出现的指令栏，只包含当前作用范围、常用操作、模型和输入框。执行后，原文仍保留在缓冲区；修改建议在正文区域预览，输入框移到正文底部，供补充要求。

审阅区显示完整的 Markdown 文档，保留标题、列表、表格和公式的排版。边线标出修改涉及的段落，当前修改会选中并定位；可以选中、复制预览内容，预览本身不能编辑。点击「对比」查看原文与建议，使用上下箭头逐处检查。焦点在预览正文时，`⌘Enter`／`Ctrl+Enter` 接受当前修改；`Esc` 收起审阅，保留尚未处理的建议。

跨文档任务在审阅区左侧列出受影响的文件，点击文件即可查看其建议。指令、来源和修改不会挤在同一个对话滚动区。底部的 `⋯` 展开任务详情，可查看来源、历史任务、Skills 和自定义指令。没有正文修改的解释、摘要等结果，也在正文大小的阅读区域展示；需要插入正文时仍先生成待审阅提议。

关闭界面只隐藏当前任务，不停止执行。运行中或有待审阅修改时，窗口保留紧凑的 AI 入口。点击其他文件会回到正常编辑，建议仍然保留；也可用 `⌘J`／`Ctrl+J` 返回任务。最后一处建议处理完后，审阅区和指令栏自动收起，归还正文空间。

运行时可用停止按钮取消，也可发送补充要求，助手在后续执行边界读取。失败后可以重试；已经完成的提议会保留。阅读模式可以发起任务和查看预览，但不能接受正文修改。

## 指定资料与查看来源

默认从选区或当前文档开始，按任务需要搜索当前工作区的 Markdown，而不是一次把整个工作区全部发送出去。

可以直接输入：

```text
结合 @notes/需求.md 和 @设计 总结这次改动。
参考 @"项目资料/会议记录.md"，检查本文是否遗漏决策。
```

也可以点击输入区的 `@`，连续勾选多篇资料或输入目录，点击「完成」返回；再次点击已勾选项可以移除。指定资料后，检索限制在所选文件／目录和当前任务文档内。

在「偏好设置 → AI」中填写排除的文件或目录，以逗号分隔，例如：

```text
private/, secrets.md
```

引用来源显示文件和行号，点击可打开并定位。来源变化后会尝试按原文重新定位；不能唯一确认时会说明位置已变化。模型自己的推断不等于资料中的事实，待审阅草稿也不应作为已存在正文的事实引用。

长文档按区间读取，读取结果带后续位置。单次输出、检索结果、任务轮次和上下文都有预算；达到限制会保留进度，由你决定是否继续。

## 审阅与应用修改

提议按文档汇总，可逐处接受或拒绝、接受单篇、全部接受，或丢弃剩余提议。也可以继续要求助手调整尚未接受的建议。

有依赖的修改需要一起接受，例如新建章节和指向该章节的链接。拒绝或修改前置提议后，依赖它的提议会标为需要更新。

接受前会检查原文、磁盘版本、其他窗口的独立编辑和路径冲突。检查失败保留提议并显示原因，不先应用一半的跨文档修改。

接受后的修改进入正常缓冲区和撤销历史：每篇文档的一批接受可以用普通撤销恢复，保存行为沿用当前自动保存设置。新文档接受后先作为未保存标签打开，保存时再选择路径；接受前不会创建磁盘文件。

## 自定义指令

在助手的 `⋯ → 自定义指令` 中填写名称和任务内容并保存，之后可以从助手中复用，也能重新编辑或删除。

支持以下变量：

| 变量 | 内容 |
|---|---|
| `{{selection}}` | 发起任务时的选区 |
| `{{document}}` | 任务文档标识 |
| `{{references}}` | 明确选择的资料 |

例如：

```text
校对 {{selection}}。统一术语，保留作者语气、链接和公式。
需要更多背景时读取 {{document}}，参考资料为 {{references}}。
```

变量只替换应用提供的值，不执行脚本。

## Skills

Skills 用于复用一套带参考资料的任务方法。支持两个位置：

- 用户级：应用配置目录中的 `ai/skills/<技能目录>/SKILL.md`。
- 工作区级：`<工作区>/.velora/skills/<技能目录>/SKILL.md`。

例如 `.velora/skills/article-review/SKILL.md`：

```markdown
---
name: article-review
description: 校对技术文章中的术语、事实与引用
---

先读取文章及用户指定的参考文档。
检查术语是否一致、结论是否有资料支持。
保留代码和公式，只提出必要的局部修改。
需要写作规范时，读取 references/style.md。
```

在助手的 `⋯ → 任务说明` 中查看、选择、禁用或重新加载。用户级与工作区级同名技能分别显示为 `user:名称` 和 `workspace:名称`，不会静默覆盖。也可在输入中显式使用 `/workspace:article-review`。

默认只加载名称与描述，正文和参考文件按需读取。相对参考资料必须位于技能目录内；不会执行附带脚本，当前版本不接入外部 MCP 工具。

## 历史任务与恢复

在指令栏的 `⋯ → 历史任务`，或正文底部 `⋯` 展开的任务详情中重新打开记录，也可清理不再需要的任务。对话、引用与待审阅修改保存在应用配置目录的 `ai/sessions/`，按工作区隔离。

切换工作区或关闭窗口时停止执行并保存状态。恢复中的未完成任务会标为中断，不会自动发送模型请求；继续或接受之前会重新检查文档内容。

## 排查连接问题

- 无法连接：确认地址、协议和模型 ID，检查网络或本地服务是否启动。
- 鉴权失败：确认 `api_key` 属于当前服务，修改后重新测试连接。
- 能回答但工具测试失败：确认该模型支持所选协议下的工具调用。
- 达到额度或限流：按服务商提示处理，或选择另一条已配置连接。
- 提议无法接受：按提示检查阅读模式、外部修改、其他窗口和关联提议；保留建议并重新生成，不强行覆盖正文。

实现与测试入口见 [AI 架构说明](architecture/ai.md)。
