# AI 使用指南

Velora 的 AI 围绕 Markdown 的阅读、写作和跨文档整理工作。助手由你主动打开，生成的修改先供审阅，接受之后才进入正文。

## 配置模型

AI 默认关闭。先在「偏好设置 → AI」开启「启用 AI」并保存，再添加模型连接。关闭时正文右键、选区工具栏、命令面板和系统菜单都隐藏 AI 入口；关闭后取消正在运行的任务，待审阅修改保留在历史中，已配置连接不会删除。

首次启用后选择 DeepSeek、OpenAI、Anthropic、Ollama 或自定义服务。预设会填好协议、地址和默认模型；新连接不继承其他连接的 Key。本地模型填写已经安装的模型名，Velora 不会自动下载模型。

常用界面只保留模型和 Key；地址、协议、预算与排除规则位于「高级」。默认连接可从下拉框选择，保存后用于新对话；切换连接不会丢弃尚未填写完的草稿。

可填写的连接参数：

| 设置 | 填写内容 |
|---|---|
| 名称 | 自己容易辨认的连接名称 |
| 服务地址 | 模型服务商的 API 地址，或本地兼容服务地址 |
| 模型 | 服务商提供的模型 ID |
| API Key | 服务商的 Key；无需鉴权的本地服务可留空 |
| 协议 | Chat Completions、Responses 或 Anthropic Messages |
| 上下文预算 | 模型支持的上下文 token 数量 |

可配置多条连接，选定默认连接后点击偏好设置底部的「保存」。连接测试会在隔离的空资料集里实际调用一次文档工具，不读取你的工作区正文；成功说明基础请求和工具调用都可以工作。修改输入后可以重新测试。

以 DeepSeek 官方为例：服务地址填写 `https://api.deepseek.com`，协议选择 Chat Completions，模型填写 `deepseek-flash`，API Key 使用官方 Key。

配置文件是应用配置目录中的 `ai.json`。macOS 路径为：

```text
~/Library/Application Support/app.velora.velora/ai.json
```

也可以直接编辑它，Key 存在 `endpoints[].api_key`，不需要系统钥匙串授权。完整连接示例：

```json
{
  "enabled": true,
  "default_endpoint": "deepseek",
  "endpoints": [
    {
      "id": "deepseek",
      "name": "DeepSeek",
      "protocol": "chat-completions",
      "base_url": "https://api.deepseek.com",
      "model": "deepseek-flash",
      "api_key": "填写你的 API Key",
      "context_tokens": 64000
    }
  ]
}
```

每次发送任务都会重新读取连接配置。新任务使用默认连接。连接选择和模型配置统一放在「偏好设置 → AI」；助手的 `⋯ → 设置` 也打开同一个窗口。保存配置不会清空对话或尚未发送的输入，浮窗顶部不显示模型切换。

## 打开助手

`⌘J`／`Ctrl+J` 打开浮动对话框。输入框支持软换行和内部滚动，`Shift+Enter` 换行、`Enter` 发送；中文组词中的确认键不会提前发送。正文右键仅保留「AI」对话入口；选中文字后点击工具栏的「AI」，会先展开五个快捷指令，选择后才启动任务。浮窗可拖动；点击右上角的侧栏图标，可把同一段对话移到右侧继续，输入和结果都会保留，再次点击可恢复浮动。

「视图 → AI 侧边栏」可以直接打开或收起右侧助手；命令面板也可搜索该入口，快捷键可在偏好设置中自行配置。已有会话会原样恢复，包括输入草稿和待审阅修改；首次打开时创建新对话。`⌘J`／`Ctrl+J` 仍用于发起新的浮动对话。

选区工具栏的「AI」菜单提供五个快捷指令，其余需求直接输入对话框：

| 指令 | 范围 | 结果 |
|---|---|---|
| 摘要 | 选区；无选区时为当前文档 | 在对话中阅读、复制 |
| 解释 | 必须有选区 | 在对话中阅读、复制 |
| 翻译 | 必须有选区，可指定目标语言 | 在对话中阅读、复制 |
| 润色 | 必须有选区 | 提出选区内的修改，等待审阅 |
| 扩写 | 必须有选区 | 保留原意和框架，在选区内补充内容，等待审阅 |

解释、翻译、润色和扩写不会因为没有选区而自动改为处理全文。阅读指令的结果只供查看和复制。润色与扩写快捷指令可以查阅其他资料，但只能修改发起时的选区。用户自由对话不受此限制：选区只是参考，可以按要求修改其他段落、当前全文或多篇文档，所有修改仍先待审阅。

## 快捷指令的默认要求

按钮上的短标签不会作为全部提示词发送。模型收到完整的任务规范，并附带选区、文档和编辑器上下文：

- 摘要：识别内容类型，提炼结论、关键事实、决策和未决事项；通常一段短文或 3—5 个要点，保留数字、条件和不确定性，避免逐段复述与开场白。
- 解释：先说明核心含义，再按内容解释代码逻辑、公式符号或术语语境；必要时查阅上下文，区分事实与推断。
- 翻译：按目标语言自然、准确地翻译，保留术语一致性、Markdown、链接、代码和公式；直接返回译文。当前目标语言初值为英语。
- 润色：修正语病、错字、标点、冗余和衔接，保留作者语气、事实与限定条件；不强行改写已经清晰的内容。
- 扩写：沿已有框架补充具体论点、解释、步骤或例子，避免重复与无关延伸；不编造数据、引用或经历，缺少关键资料时指出缺口。

润色、扩写还会收到共同的工具要求：必须通过 `propose_edit` 提出选区内的待审阅修改；完成后简述结果，不在对话中重复粘贴原文、改文或差异对照。默认任务要求位于 `resources/ai/prompts/en-US/` 与 `resources/ai/prompts/zh-CN/`，按界面语言选择；其他语言使用英文。指令装配见 `src/ai/instructions.rs:PromptProfile::capture`。每个任务首次发送时保存指令、语言和 Skills 目录快照，后续修改偏好或切换界面语言只影响新任务，历史恢复与续聊仍沿用原前缀。

## 对话与正文审阅

阅读结果留在对话中，正文保持当前阅读位置。浮窗与侧栏不重复显示快捷指令；历史、来源、Skills、自定义指令与连接设置通过 `⋯` 按需打开。侧栏的输入区始终固定在底部，空白会话、已有消息和错误提示均不改变它的位置。输入、引用和发送位于同一张卡片内。

写作建议在编辑器原位显示：删除内容以红色标出，新增内容以绿色标出；标题、列表、代码和公式继续使用 Markdown 排版。修改块底部的勾和叉用于接受、拒绝当前修改，浮窗中可切换文件和修改位置，也可接受单篇或全部修改、重新生成。`⋯ → 丢弃修改` 可一次拒绝剩余建议；`⋯ → 返回正文`／`修改审阅` 可在原文和预览之间切换。

预览可以选中和复制，本身不能编辑。接受前，正式缓冲区与磁盘文件均不改变。焦点在正文审阅区时，`⌘Enter`／`Ctrl+Enter` 接受当前修改；接受后用普通撤销恢复。

可以直接要求「在光标处插入一段过渡」「删除这段重复说明」或「把结论整理成一篇新文档」。写作结果的插入、替换、删除与新建同样先预览，再接受；新文档先成为未保存标签。

关闭浮窗只隐藏对话，不停止执行，也不丢弃待审阅修改。切换到其他标签会显示它的正文；回到原标签会恢复待审阅预览、当前差异和滚动位置。主动选择「返回正文」后则保持原文显示，不因切换标签强制重开。每次按 `⌘J`／`Ctrl+J` 都开启一段独立用户对话，重新捕获当前文档与选区；在这段对话的输入框里可以连续追问，浮窗和侧栏保留同一段历史。五个快捷指令独立执行，结果不带追问输入框；重新运行时不继承上一次的上下文。之前的用户对话与快捷结果在 `⋯ → 历史任务` 中分组显示，选择后在侧栏恢复。运行中可停止；用户对话还可发送补充要求。用户对话失败后可重试，已有提议会保留；快捷指令重试时重新执行，不续接旧的模型上下文。阅读模式仍可问答与查看建议，但不能接受正文修改。

## 指定资料与查看来源

每次发送都提供工作区路径、已打开标签页的元数据、活动标签、光标的行列与字节位置、当前选区及光标附近的有限正文。标签列表包含分屏中的文档，不会一次发送所有标签页的全文。较长选区带截断标记，助手可按需分段读取。

任务保留发起时的文档与选区，同时附带发送当刻的编辑器状态。停靠在侧栏的用户对话可在切换标签后继续，当前标签与光标作为新一轮资料提供。助手按需搜索当前工作区的 Markdown；显式选择的参考资料也会列入上下文。正文有变化时，接受前重新校验，不按过期坐标覆盖。

可以直接输入：

```text
结合 @notes/需求.md 和 @设计 总结这次改动。
参考 @"项目资料/会议记录.md"，检查本文是否遗漏决策。
```

也可以点击输入区的 `@`，连续勾选多篇资料或输入目录，点击「完成」返回；再次点击已勾选项可以移除。指定资料后，检索限制在所选文件／目录和当前任务文档内。

在「偏好设置 → AI」中填写排除的文件或目录，以逗号分隔，例如：

```text
private/, secrets.md
```

排除规则也适用于默认上下文：被排除文档的选区和邻近正文不会附带发送；当前目标被排除时，任务会提示原因。

回答中的引用链接可以打开资料；`⋯` 中的来源列表提供文件和行号，点击可定位。来源变化后会尝试按原文重新定位；不能唯一确认时会说明位置已变化。模型自己的推断不等于资料中的事实，待审阅草稿也不应作为已存在正文的事实引用。

请求优先放置稳定指令与资料，再附加本轮编辑器状态和要求；多轮对话保留已发送的消息前缀，追加新内容。快捷指令的固定要求也位于变化的选区数据之前。实际缓存命中由模型服务端决定。

长文档按区间读取，读取结果带后续位置。单次输出、检索结果、任务轮次和上下文都有预算；达到限制会保留进度，由你决定是否继续。

## 审阅与应用修改

提议按文档汇总，可逐处接受或拒绝、接受单篇、全部接受，或丢弃剩余提议。也可以继续要求助手调整尚未接受的建议。

有依赖的修改需要一起接受，例如新建章节和指向该章节的链接。拒绝或修改前置提议后，依赖它的提议会标为需要更新。

接受前会检查原文、磁盘版本、其他窗口的独立编辑和路径冲突。检查失败保留提议并显示原因，不先应用一半的跨文档修改。

接受后的修改进入正常缓冲区和撤销历史：每篇文档的一批接受可以用普通撤销恢复，保存行为沿用当前自动保存设置。新文档接受后先作为未保存标签打开，保存时再选择路径；接受前不会创建磁盘文件。

## 自定义指令

「偏好设置 → AI → 指令」可编辑通用写作偏好，以及摘要、解释、翻译、润色和扩写的默认要求。编辑区支持换行；切换指令保留草稿，点击偏好设置底部的「保存」后生效。「恢复默认」恢复当前指令，其他指令保持不变。

默认要求随界面语言切换，自己填写的指令不会被自动翻译或覆盖。通用偏好用于所有新任务；内置快捷指令的阅读权限、选区限制与审阅流程始终有效。已开始的任务保留原指令快照。

在助手的 `⋯ → 自定义指令` 中填写名称和任务内容并保存，之后可以从助手中复用，也能重新编辑或删除。

支持以下变量：

| 变量 | 内容 |
|---|---|
| `{{selection}}` | 发起任务时的选区 |
| `{{document}}` | 任务文档标识 |
| `{{references}}` | 明确选择的资料 |

例如：

```text
校对 {{selection}}。统一术语，保留作者语气、链接和公式。
需要更多背景时读取 {{document}}，参考资料为 {{references}}。
```

变量只替换应用提供的值，不执行脚本。

## Skills

Skills 用于复用一套带参考资料的任务方法。支持两个位置：

- 用户级：应用配置目录中的 `ai/skills/<技能目录>/SKILL.md`。
- 工作区级：`<工作区>/.velora/skills/<技能目录>/SKILL.md`。

例如 `.velora/skills/article-review/SKILL.md`：

```markdown
---
name: article-review
description: 校对技术文章中的术语、事实与引用
---

先读取文章及用户指定的参考文档。
检查术语是否一致、结论是否有资料支持。
保留代码和公式，只提出必要的局部修改。
需要写作规范时，读取 references/style.md。
```

在助手的 `⋯ → 任务说明` 中查看、选择、禁用或重新加载。用户级与工作区级同名技能分别显示为 `user:名称` 和 `workspace:名称`，不会静默覆盖。也可在输入中显式使用 `/workspace:article-review`。

在助手的 `⋯ → 任务说明` 中切换启用状态，点击“使用”把相应指令加入当前草稿，随后仍由你决定何时发送。来源区分个人和工作区；“重新加载”刷新目录中的任务说明。自定义指令可在 `⋯ → 自定义指令` 中选择并编辑。配置读取失败时，保存、删除和启用切换暂不可用，已有内容仍可选中、复制；修复配置并刷新设置后恢复编辑。

默认只加载名称与描述，正文和参考文件按需读取。相对参考资料必须位于技能目录内；不会执行附带脚本，当前版本不接入外部 MCP 工具。

## 引用来源

助手的 `⋯ → 来源` 按条目列出文件、行号和简短摘录。用方向键浏览，点击或按 Enter 调用原文定位；Esc 返回对话。定位沿用原有文档打开与内容校验，浏览来源不会自动应用正文修改。来源更新时保留仍有效的选择，新任务从首项开始。

## 历史任务与恢复

在助手的 `⋯ → 历史任务` 中，记录按对话与快捷指令分组。用方向键浏览、Enter 恢复，或直接点击记录；Esc 返回原对话并保留输入草稿。选中记录后，标题栏的删除按钮可清理该记录。对话、引用与待审阅修改保存在应用配置目录的 `ai/sessions/`，按工作区隔离。

切换工作区或关闭窗口时停止执行并保存状态。恢复中的未完成任务会标为中断，不会自动发送模型请求；继续或接受之前会重新检查文档内容。

## 排查连接问题

- 无法连接：确认地址、协议和模型 ID，检查网络或本地服务是否启动。
- 鉴权失败：确认 `api_key` 属于当前服务，修改后重新测试连接。
- 能回答但工具测试失败：确认该模型支持所选协议下的工具调用。
- 达到额度或限流：按服务商提示处理，或选择另一条已配置连接。
- 提议无法接受：按提示检查阅读模式、外部修改、其他窗口和关联提议；保留建议并重新生成，不强行覆盖正文。

实现与测试入口见 [AI 架构说明](architecture/ai.md)。


## 提供商预设的参考

预设目录集中在 `src/ai/providers.rs`，协议与工具兼容设置由同一条目录记录声明。服务地址与模型示例参考 [OpenAI 官方快速入门](https://developers.openai.com/api/docs/quickstart)、[DeepSeek 官方 API 文档](https://api-docs.deepseek.com/guides/codex) 与 [Claude Messages API](https://platform.claude.com/docs/en/api/messages/create)。模型名称可按账户可用范围修改，连接测试会检查实际的工具调用。
