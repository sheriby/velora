# AI 文档助手

当前实现位于 `src/ai.rs`、`src/ai/` 和 `src/editor/ai_assistant.rs`。后台 Agent 只读取文档快照和修改提议；正式内容仍以 `TextBuffer` 为准。

## 入口与窗口归属

`AiCommand` 定义内置任务及选区要求。选区工具栏、正文右键、命令面板、菜单和快捷键汇到 `Editor:open_ai_assistant`。默认快捷键是 `⌘J`／`Ctrl+J`；常用任务可单独配置快捷键。

「视图 → AI 侧边栏」与命令面板、可配置快捷键共享 `Editor:on_toggle_ai_sidebar`，开合已有任务保留输入、模型历史和提议；无任务时才新建。分屏由叶节点延后交给窗口宿主，初始布局随目标快照一同传递，避免延迟创建时先修改旧任务的布局。`⌘J`／`Ctrl+J` 仍每次发起独立浮动对话。

普通文档渲染与 `Editor:render_split_workspace` 都挂载同一套浮动对话、可选侧栏、正文审阅区及动作处理。编辑器组宿主会提前返回自己的渲染路径，不能只在普通文档分支添加 UI。

`Editor:open_ai_target` 在操作发生时固定文档身份、原始选区、源码字节区间与读取版本。分屏把目标交给宿主窗口；同一窗口只展示一个任务，但任务状态分别保存。每次从正文发起指令都创建独立任务，重新捕获文档、选区与版本，不继承其他任务的输入、模型历史、提议或权限。仅在当前对话输入补充要求才续用原任务；快捷键重新唤起也创建新会话；多轮追问只在原用户对话中进行。浮窗与侧栏共用输入、会话和结果实体，切换只改变布局，不重复发送请求；隐藏不取消执行。阅读模式可以发起任务，接受修改仍被编辑器层阻止。

普通启动仅从 `ai.json` 初始化 `AiFeature` 的启用状态，不创建 AI 任务或读取工作区全文。缺少开关的既有配置也默认关闭；渲染与命令共用内存开关，关闭后取消全部窗口中的运行任务并保存待审阅状态。配置在主动打开助手时加载，发送和测试连接直接使用配置中的 `api_key`，不访问系统钥匙串或凭据管理器。

## 正文审阅与焦点

`editor/ai_assistant/workbench.rs` 管理浮动对话与可选侧栏。五个快捷指令集中在选区工具栏的菜单，浮窗与侧栏不重复显示；来源和配置通过菜单查看，模型选择仅保留在设置中。输入区使用统一卡片和无边框的原生文本输入，引用与发送置于卡片底部。侧栏空白区与消息区统一填充剩余高度，输入卡片始终位于底部；重试等状态操作位于卡片上方，避免首条消息或错误提示移动输入区。整个浮窗顶部可抓取，拖动在捕获阶段处理，按钮的按下独立拦截，避免正文选择与拖动互相截断。`context.rs` 捕获每次请求时的工作区名称、所有分屏标签的相对路径元数据、活动文档、光标、选区与有限邻近正文，原始任务选区另行保留。

侧栏宿主明确使用纵向 flex 布局，避免内部百分比宽度退回内容宽度而把空输入框压成窄条。输入区占满可用宽度，批量接受与发送操作对齐右侧；浮窗与侧栏共用输入卡片，以细边框提示焦点，不给整张卡片叠加外扩焦点环。正文与修改预览的切换放入更多菜单。“更多”使用 Kit `DropdownMenu`／`PopupMenu` 就地展开，保留会话与草稿；历史、任务说明、自定义指令与来源仍在面板内查看，设置打开偏好设置窗口。菜单动作校验展开时的会话身份，避免旧菜单操作新任务。编辑器的关闭临时界面绑定限定在 `VeloraEditor` 上下文，原生菜单的取消动作优先处理 Esc。

普通窗口与分屏宿主共用 `render.rs:render_ai_sidebar_layout`，由 Kit `ResizablePanelGroup` 管理正文区域和 AI 侧栏的宽度与指针拖动。`AiSidebarLayout` 属于窗口宿主，保留运行期间的布局状态，切换任务、隐藏或回浮窗不重置侧栏宽度；窗口缩放按当前可用空间约束尺寸。0.7.3 的分隔条没有键盘入口，应用通过共用的 `ui/resize.rs:PanelResizeHandle` 补充 `Splitter` 语义与左右箭头、Home／End，并配置焦点句柄自身的 Tab 属性，尺寸仍调用 Kit `ResizableState:resize_panel`，不另写一套拖动或边界算法。

标题栏固定提供历史按钮，停靠与浮动共用：点击进入按工作区保存的会话列表，选中后恢复并保留输入框，可继续追问。浮动窗标题栏另有收起按钮；收起后正文右下角显示 AI 图标方块，点击恢复原位置与输入，停靠侧栏不提供收起。浮动窗右下角提供缩放手柄，拖动改宽高，尺寸夹在视口内；用户拖过之后保持该尺寸，空对话也可调整。

窗口放不下工作区导航、正文与 AI 侧栏时，同一任务临时以浮窗显示，停靠按钮说明需要拓宽窗口；不更改 `expanded` 偏好，不新建会话或重置输入、消息与滚动。空间恢复后继续使用原有侧栏状态。可停靠判据和缩放边界读取同一份 `workspace_navigation_width`，工作区展开或改宽后，正文仍有独立的最低空间。

`experience.rs:refocus_visible_ai_review` 在工作区导航关闭后把焦点交回当前显示的审阅正文，分屏由宿主统一调度。

`experience.rs` 管理原位审阅。`inline_review.rs:tracked_document` 从正式原文与待接受版本生成包含删除和新增块的只读投影；块边界取自两份文档的既有解析树，不重新猜测 Markdown 语法。删除为红色、新增为绿色，当前修改的底部操作区提供接受与拒绝，使用 Kit `Button` 并参与正常行布局，不悬浮遮住正文。跨文档导航、重试和批量接受留在浮窗中。

阅读结果与对话使用 Kit `Message`、`MessageScroller` 和 `TextViewState`，由 `messages.rs:MessageTranscript` 持有会话内的展示状态。消息按会话身份与源序号保持身份，只在进入可见区或预绘区时创建富文本状态；流式追加与完成共用同一视图，不拼接整段对话或创建新 `Editor`。停靠、回浮窗及追加内容保留选区和滚动；正在跟随时显示最新内容，向上阅读后不抢位置。快捷指令隐藏自动生成的首条指令，完成后同样提供追问输入，追问与回复照常显示。工具调用记录在 `SavedSession:tool_calls`，按 `message_index` 归属发起它的 assistant 消息，在对话流里内联渲染成工具链条：模型还没吐字时逐步展开（一行一次调用），正文开始后自动收起，标题行可手动展开；失败轮回滚时一并清理，恢复会话时停在 Running 的记录按失败收口。模型思考过程存进 `ChatMessage:thinking` 只用于展示，「偏好设置 → AI」的开关控制是否渲染，同样默认收起、灰色小字、可展开。

消息使用 Kit 安装的 Base TextView 主题默认值；0.7.3 的 Component 兼容层没有图片源解析接口，因此直接使用 Base 的 `image_source`，仍复用项目唯一的图片路径解析器。代码高亮继续使用现有语言规则和配色，每份主题保留同一个高亮闭包，代码复制使用 Kit `Clipboard`。公式和图表沿用既有渲染器，通过 GPUI `Asset` 在后台生成及缓存，资源就绪后刷新布局。括号公式混排由现有只读 `Block` 渲染，复用原语法和选择逻辑，不重写判据。

修改审阅仍使用只读 `Editor`，保留块树、差异导航与文档虚拟化；`ai_result_preview` 不注册关闭拦截、不修改窗口标题或脏标记。消息展示没有正文写入口，选区和复制由 Kit Root 管理；消息或内嵌只读块的焦点均隔离正式文档的快捷键。链接、锚点与图表预览延后到当前事件结束后处理，避免跨实体或窗口重入。

宿主的 `document_listener` 在分派正文快捷键前检查浮窗输入、对话和审阅焦点，避免正式文档旧选区截获复制或误删原文。行内审阅按钮延后到当前事件结束，再访问宿主与窗口，且校验文档和版本，避免 GPUI 重入。

最后一处建议处理完后归还正文，对话仍可继续。文件导航只暂时隐藏审阅，并用标签的恢复标识记录返回位置；回到原标签复用已有投影实体、差异索引和滚动位置。分屏导航把来源标识延后交给宿主，迟到的结果不会覆盖其他标签。主动返回正文和临时切走分别处理；隐藏对话不关闭审阅。新入口会暂存原任务，后台执行继续，待审阅修改、输入草稿与投影保留，可从历史入口明确恢复；普通标签回切恢复该文档最后查看的审阅状态；用户明确停靠的对话可跨标签持续使用。即使运行代数相同，后台结果与实时快照请求也必须按会话标识路由，不能落到当前新任务。延迟发送与审阅操作还分别校验输入框身份、会话身份，发送前再校验任务所属文档。切换工作区时取消并保存所有暂存任务。

`SavedSession:kind` 区分快捷指令和用户对话，并随历史持久化。快捷指令完成后同样可以追问，多轮后按对话方式继续；停靠不会改变类型；重试仍是一次性的快捷指令清空模型历史和旧提议重新执行，带追问的会话按对话回滚失败轮。旧记录携带只读或选区权限时归入快捷指令。用户对话的选区是参考资料，不设置 `selection_scope`；可在一次任务里对多篇文档提出修改。侧栏用户对话允许活动文档变化，快捷指令仍执行各自的阅读或选区约束。

对话和自定义指令正文使用 Kit `TextareaState`，语言、指令名称与资料路径使用 `InputState`，由会话持有状态与订阅。通用的布局、选区、IME 和输入撤销由 Kit 负责；对话输入随内容增长，并在持有当前窗口的 `InputEnter` 动作中提交，组词回车与 Shift+Enter 不发送。指令正文中的回车只换行，表单修改不进入文档撤销栈。

资料候选与手动添加的路径使用同一份 Kit `Checkbox` 列表。候选顺序不随勾选改变，额外路径放在顶部；选择状态只维护在会话的 `references` 中。

默认要求集中在 `resources/ai/prompts/en-US/` 与 `resources/ai/prompts/zh-CN/`，`ai/instructions.rs:default_instruction` 按界面语言选择，未知语言回退英文；界面标签与任务正文分开。`PromptProfile:capture` 装配固定系统要求、通用写作偏好、Skills 目录与快捷任务正文。润色、扩写附带独立的工具交付要求，自定义任务正文不会移除工具层的阅读或选区权限。`ai_polish_sends_full_task_requirements_and_keeps_the_document_unchanged_without_a_proposal` 通过本地 HTTP 夹具检查实际请求和工具范围，并验证没有修改建议时正文保持不变，防止只发送按钮标签。

操作图标需要在 `main.rs:VeloraAssets` 注册；磁盘上存在 SVG 并不代表产品能加载。AI 资源回归使用正式资源源逐一解析并栅格化，断言实际存在可见像素。

## 运行时与工具

固定使用 `yoagent = 0.25.7` 的原生 `agent_loop`，框架依赖集中在 `src/ai/runtime.rs`。比较过 Rig 的 Agent／工具接口后，本实现采用 yoagent 已有的多轮工具执行、运行中追加指令、取消、执行预算、上下文压缩和 MockProvider；应用负责文档身份、资料边界、持久化和审阅。没有嵌入 JavaScript 运行时，也不依赖外部 Agent 进程。

`DocumentTool:execute` 将文档操作放到后台，读取当前窗口已打开文档时，通过 `SnapshotBridge` 请求前台取得最新缓冲区快照；后台不持有 GPUI 实体。macOS 的 GCD 后台线程栈较小，`run_blocking` 使用有显式栈空间的专用线程运行 Tokio，避免调试构建的 Agent／HTTP future 栈溢出。原生菜单动作延后到当前事件结束再访问窗口，避免重入窗口派发。前台合并流式事件，代数检查阻止停止后或旧会话的迟到事件污染当前任务。时长由外层超时统一控制，框架保留轮次和 token 预算；工具执行中被强制超时时，使用完整轮次检查点恢复对话，避免留下未配对的工具消息导致后续请求被拒绝。每轮结束保存检查点，不逐 token 重算差异。

工具调用消息原样交给 agent loop，不在 provider 与 loop 之间重拼或重试；参数被截断时把带工具名的错误直接报给用户，避免空名字的调用被当成一次真实工具调用执行。工具结束发出 `ActivityDone`，面板不再保留上一次「检索资料」之类已经结束的文案。

仅注册以下工具：

| 工具 | 用途 |
|---|---|
| `list_documents` | 按目录和偏移分页列出文本文档 |
| `find_documents` | 按 glob 模式匹配文件名；`*` 与 `?` 不跨 `/`，递归写 `**`，`folder` 只是模式求值的起点 |
| `search_documents` | 整串字面量的文本搜索（不按空白拆词），复用编辑器的 ripgrep 固定字符串引擎，返回路径、行号和有限片段 |
| `read_document` | 按行或字节位置读取；优先当前未保存内容与本任务有效提议 |
| `get_outline` | 由既有 Markdown 解析器取得标题与行号 |
| `propose_edit` | 以唯一匹配的原文片段提出替换；空原文表示追加 |
| `propose_insert_at_cursor` | 在本次请求捕获的光标处提出插入，重复插入映射到待审阅版本 |
| `propose_document` | 提出新的文本文档 |
| `reset_proposal` | 丢弃旧提议，供依据变化后重新生成 |
| `read_skill` | 按需读取任务说明与目录内参考资料 |

`AiWorkspace:tool_allowed` 同时约束运行时注册与实际调用。摘要、解释、翻译不注册任何修改工具；润色、扩写只能使用选区内的片段修改，不能新建文档或走光标插入。`SelectionScope:allowed_in` 校验原始版本以及选区外的前缀和后缀；`ChangeSet:propose_within` 在允许区间内唯一匹配。接受端再次校验边界，部分接受后更新选区与版本。光标插入校验文档版本，并将坐标映射到已有提议；坐标落入其他修改内部时拒绝插入。

不注册 shell、任意文件写入、移动、删除、脚本或外部 MCP 工具。`@文件`、`@目录` 与资料选择器限制检索范围；配置排除项同样约束读取与新文档提议。磁盘路径经过工作区根、相对路径和符号链接边界校验。

哪些文件算文档只有一处判据：`file_url.rs:is_text_document`——扩展名表加 `.env`、`.gitignore` 这类点文件名，二进制与无扩展名文件不进名单；文件名单、路径校验与资料范围共用它，`get_outline` 是唯一仍限 Markdown 的工具。给模型的路径一律是工作区相对路径：换算只在 `ai_assistant.rs:ai_workspace_relative_path`，`ai_document_id` 与上下文里的标签 `path` 共用，工作区外的文件不带 `path`，工作区本身只报名字。

每次读取最多 300 行／32 KiB，返回后续字节位置和截断标记，超长单行也能连续读取。搜索最多 50 条结果，错误摘要最多 20 条。搜索的磁盘文件与侧栏共用同一份内容缓存（单文件 20 MiB、总预算 128 MiB），按 CPU 核数并行扫描；活缓冲、新建文档与待审阅内容仍逐个走任务快照。`read_document`/`get_outline` 的未打开磁盘文件有 16 MiB 单文件载入预算，任务快照另有 64 MiB 预算；超限会返回可见错误，较大文件可先在编辑器中打开再分段读取。工具输出和上下文由运行时继续限制。普通任务最多 32 轮、10 分钟，连接探针使用更小预算。

## 提议与接受

`ChangeSet` 保存基准与完整待审阅文本，`Proposal:edits` 缓存有时间上限的行差异，再收紧首尾相同内容以减少长行复制。流式回答不会改变正文、普通撤销栈或文件历史。

Agent 读取了某篇待审阅文档后，后续提议会记录对它的依赖。相关修改需要一起接受；拒绝、重置或继续修改前置提议会使依赖者失效，保留内容供查看和重新生成。部分接受后更新基准，后续工具读取继续使用剩余提议。

`Editor:accept_ai_proposals` 先检查所有目标：阅读模式、工作区路径、基准内容、磁盘版本、其他窗口的独立脏副本、新文档碰撞和关联依赖。预检全部成功后才写缓冲区。每篇文档一批接受对应一个普通撤销组，保留已有编码与行尾；同文档分屏复用已有共享缓冲区同步机制。

接受新文档会创建带建议文件名的未保存标签，保存时走原有另存为流程。接受前不会创建磁盘文件。已有文档接受后依照正常自动保存设置处理。

来源记录保存路径、读取区间、行号、版本与有限原文片段。定位先检查读取版本；版本变化后仅在片段仍唯一匹配时重新定位，否则说明无法确定原位置。回答使用只读 Markdown 投影；链接通过宿主窗口打开，不能借回答中的 wikilink 创建文件。

## 配置、指令与恢复

「偏好设置 → AI」是连接编辑、默认连接、协议、Key、上下文预算、资料排除和工具连接测试的唯一界面。助手设置入口延后打开并复用此窗口，不维护第二份连接表单，也不取消当前任务。配置保存推进 `AiFeature` 的版本号，现有会话下一帧按版本刷新设置；发送前仍重新载入配置。输入和删除先暂存，底部保存后才落盘，取消不写文件。AI 设置独立保存到应用配置目录的 `ai.json`，包含多连接、默认连接、上下文预算、自定义指令、排除项和禁用 Skills。支持 Chat Completions、Responses、Anthropic Messages；本地兼容服务允许空密钥。连接测试会在隔离的空资料集里验证实际工具调用，失败不会伪装为成功。

`ai/providers.rs:ProviderPreset` 统一声明内置服务的协议、默认地址、模型、上下文预算、Key 要求与供应商兼容适配；新增兼容服务无需改写表单。`Endpoint:provider` 为可选的服务身份，旧记录按目录地址识别。配置暂存允许清空 Key；实际发送和测试通过 `Endpoint:request_config` 检查必要凭据，本地与自定义服务支持空 Key。

偏好设置用默认连接下拉与折叠高级区控制信息密度，连接草稿独立保留，未完成的输入不阻止切换连接，保存时统一校验。删除连接后恢复已有草稿，不重新创建字段覆盖输入。停用 AI 时保留连接草稿和已清空的 Key；无效数字预算沿用上一个有效值。

指令编辑位于偏好设置的独立页签，复用 Kit `Textarea`；`pages_ai/instructions.rs:InstructionDraft` 维护当前编辑项，切换时暂存到 `AiSettings:quick_instructions`。空白或等同当前语言默认值的正文不生成覆盖项，恢复默认仅移除当前项。语言切换先暂存自定义草稿，再加载新语言的默认要求，未保存内容不写入配置。

API Key 与连接一起保存在 `ai.json` 的 `endpoints[].api_key` 字段，可以在设置中保存，也可以直接编辑文件；空字符串用于无需鉴权的本地服务。保存仍使用既有原子写入，失败时保留原配置。Unix 文件权限限制为当前用户读写；调试输出隐藏密钥，会话记录不保存密钥。删除连接同时移除其配置中的 Key。

macOS 配置文件为 `~/Library/Application Support/app.velora.velora/ai.json`，例如：

```json
{
  "enabled": true,
  "default_endpoint": "deepseek",
  "endpoints": [
    {
      "id": "deepseek",
      "name": "DeepSeek",
      "protocol": "chat-completions",
      "base_url": "https://api.deepseek.com",
      "model": "deepseek-flash",
      "api_key": "填写你的 API Key",
      "context_tokens": 64000
    }
  ]
}
```


自定义指令支持 `{{selection}}`、`{{document}}`、`{{references}}`，仅替换应用提供的值，不递归展开变量或执行脚本。Skills 采用 `SKILL.md`：用户级目录为应用配置目录下的 `ai/skills`，工作区级为 `.velora/skills`。列表只加载名称和描述；正文及相对参考资料按需读取。同名任务以 `user:`／`workspace:` 区分，支持禁用和重新加载。

任务说明面板用 Kit Checkbox 和 Button 将启用、来源、描述与使用动作分组；切换请求采用控件给出的目标布尔值，使用只追加指令到草稿，不自动发送。自定义指令的控件按名称持有身份，手写配置的同名项使用独立身份空间，删除按内容快照定位。只读配置以原生 Input／Textarea readonly 呈现，保留复制；读取失败原因是只读的唯一依据。重新加载成功解除只读，只撤下该配置错误的提示；其他任务的错误仍保留。重新加载失败锁住写入并保留原配置。辅助面板的列表及保存操作通过 `ui:scroll_focus_region` 在焦点首次进入时最小滚动入视，滚动条由 Kit 提供；该适配与欢迎页共用，不另写按钮或键盘激活机制。

来源面板使用 Kit `List`／`ListState` 和 `source_list:SourceList` delegate。`SavedSession.workspace.source_records` 是事实源，列表只在快照或任务身份变化时同步投影，并按完整记录保留选择；行高固定为 rem 尺度，摘录展示限长，视口之外的行不布局。确认先释放列表更新租约，再验证会话与列表身份、当前模式和模态状态，最后调用既有 `Editor:open_ai_source`。空态与重新进入会初始化候选，不沿用其他任务的滚动位置。辅助面板反馈使用 Kit Alert 独立限高滚动，候选区保留自身滚动所有者。

`Editor:open_ai_source` 优先匹配保存后的文档绑定与标签缓存中的文档身份，复用外部文件和未命名草稿的未保存内容；同一缓存匹配判据同时服务内容读取与路径定位。来源已显示在另一分屏时激活该组，否则沿当前组的正常打开流程恢复标签。分屏打开延后执行，重新核对任务身份、来源模式与模态状态，避免重入宿主。未绑定且不在缓存中的路径仍须通过工作区规范路径边界校验；定位只选择经版本或唯一摘录校验的原文，不写入磁盘。

会话按工作区身份保存到应用配置目录下的 `ai/sessions/<工作区哈希>/`。记录包括对话、来源、模型历史、提议、目标与中断状态，不保存密钥或实体句柄。异步写入序号避免旧检查点覆盖新状态；删除标记避免迟到写入重新创建已清理记录。

历史面板使用 Kit `Command`／`CommandGroup`／`CommandItem` 管理分组候选、键盘选择与虚拟滚动，`AiSession` 保留 `CommandState`，文件摘要仍由异步读取结果提供。加载中和空态分别显示进度与本地化占位；标题栏删除针对当前候选，恢复回调读取该帧安装的路径映射，并验证当前会话持有相同列表实体。初次挂载与加载完成后在预绘制阶段一次性聚焦列表，避免焦点落到未显示的查询框；回调仅捕获弱编辑器和列表身份，不持有列表本身。辅助浮窗的空间扣除标题栏、状态栏及 rem 边距，大字号不会覆盖状态栏。

切换工作区与关闭窗口会取消执行并保存最后状态；重开历史会话不会自动发请求。恢复后仍需重新校验文档基准才能接受修改。无法解析的版本保留原文件并报错。

## 验证

`cargo test --bin velora ai_` 覆盖确定性多轮工具链、修改审阅、路径范围、引用、配置写入事务、恢复、取消／超时、分屏与真实 GPUI 入口。`src/ai/runtime/protocol_tests.rs` 使用本地 HTTP／SSE 夹具验证三种协议的“工具调用 → 工具结果 → 下一轮请求”，CI 无需真实 API Key。小栈回归在子进程中从 512 KiB 线程启动实际 HTTP 工具链，主用例断言进程成功退出，防止再次被普通测试线程的大栈掩盖。

`ai_runtime_configured_backend_reads_proposes_and_verifies_an_exact_change` 默认使用 MockProvider；仅显式提供 `VELORA_AI_LIVE_CONFIG` 时连接指定服务。默认读取该配置里的 `api_key`；也可通过进程环境 `VELORA_AI_LIVE_KEY` 临时覆盖测试密钥，命令行和日志不写密钥。真实服务验证只操作内存夹具，断言正式原文未变、待审阅结果准确。


## 请求前缀

`ai/context.rs:task_prompt` 将固定要求与易变资料分开：内置快捷指令的完整要求置于首轮最前；工作区名称、标签相对路径与显式资料按稳定顺序排列，原始选区只在首轮写入。当前活动文档、光标、选区与邻近正文随后提供，本次要求放在末尾。用户对话后续轮次只追加本轮状态和要求，不重新注入原始选区，也不改写已发送的历史。固定系统指令和工具定义不随光标变化；Skills 目录按标识排序，避免目录枚举顺序干扰前缀。

每个任务在首次有效发送时创建并持久化 `SavedSession:prompt_profile`，续聊、快捷重试与历史恢复复用原快照。修改偏好设置、界面语言或 Skills 目录不会重装既有系统前缀，新任务使用新设置；旧版无快照的记录在下一次发送时补建。本地 HTTP 回归实际发送两轮请求，检查修改偏好与语言后系统及消息前缀仍逐字相同。

三种协议的本地 HTTP 用例检查工具续轮和新一轮对话的消息前缀、系统指令及工具定义；Anthropic 断点元数据移动时，检查正文前缀保持一致。服务端缓存是否命中不由客户端测试保证；上下文预算触发的历史压缩仍按运行时规则处理。
