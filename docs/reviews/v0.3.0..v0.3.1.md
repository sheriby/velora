# Velora 代码评审 · v0.3.0..v0.3.1（聚焦 Vim 与 gpui-kit AI）

- 固定点：`v0.3.0` = `32344ce`；`v0.3.1` = `51d609b`（评审在 `.review/worktrees/v0.3.1` 隔离树进行，主工作树未改产品代码）
- 模式：diff（`v0.3.0..v0.3.1`）。Vim 为全新增代码；AI 在 v0.3.0 已成型，本报告按当前固定点审其运行时与界面，并重点看 v0.3.0 之后的两笔 AI 修复。
- 评审块与方式：Vim 核心 5 文件 + 编辑器/配置/组件集成面逐文件读；AI 运行时、工具边界、浮窗/审阅/Kit 界面并行只读侦察后由主线复核。测试模块只作行为证据，不作缺陷审。
- 总体结论：Vim 的五类根因——**反向动作区间、字符可视端点、缩进路径、保存关闭时序、编辑期整篇序列化**——各自带出多条用户可见错误；其中宏自递归可崩进程、语言输入框被抢键可误改正文，建议在下一版前必修。AI 侧共 27 条（必修 4、建议 23）：自定义指令能存不能用、失败轮重试会把同一句要求重复送进模型历史、排除项可被符号链接别名绕过、默认资料边界会把 `.env` 等敏感文本交给远程模型；另有代码文档半支持、新文档提议生命周期泄漏、停止后工具记录永久转圈、审阅投影在渲染期重建等一批边界问题。功能缺口单独列在末尾。

## 维度一 · 仓库既有不变量与 GPUI 契约

### V-01【必修】普通模式下代码块语言输入框被 Vim 抢键，可能误改代码正文
- 位置：`src/editor/vim.rs:vim_focused_block`、`src/components/block/input.rs:accepts_text_input`。
- 触发：开启 Vim，处于普通模式，点击代码块语言标签使 `code_language_focus_handle` 获得焦点，然后输入 `rust` / `go`。
- 实际：`vim_focused_block` 把语言框当成「聚焦块」；窗口级拦截器先调用 `vim_key_down`，可打印键被当作 Vim 命令（`r` 等待替换、`u` 撤销、`o` 新行/进插入）。同时 `accepts_text_input` 无视焦点目标，直接返回块级的 `vim_accepts_text_input`（普通模式为 false），系统文本输入与 IME 一并关闭。该输入框在普通模式下既收不到字符，又会让字符去改正文。
- 预期：焦点在语言框时 Vim 直通，语言框自己的按键处理（`components/block/interactions/code_language.rs`）接管。
- 建议：`vim_key_down` 在语言框聚焦时返回 false；`accepts_text_input` 在语言框聚焦时返回 true。补一条「普通模式点击语言标签 → 输入 rust → 语言变更且正文不变」的窗口用例。
- 置信度：high（两条路径都已核对）；验证状态：代码路径核对，未跑窗口用例。

### V-02【必修】Vim 的 Esc 排在 LaTeX/`[[` 补全与 Mermaid 预览之前，浮层关不掉
- 位置：`src/editor/render/paint.rs:render`（拦截器顺序）与 `src/editor/vim.rs:vim_key_down`。
- 触发：公式块里输入 `\al` 打开 LaTeX 补全，按 Esc；或 Mermaid 预览打开时按 Esc。
- 实际：`vim_key_down` 是拦截器第一步并 `stop_propagation`；插入模式下 Esc 被当成「退出到普通模式」，普通模式下被当成 `EnterNormalMode`，`latex_completion_key_down` / `wikilink_completion_key_down` / `mermaid_preview_key_down` 的 Esc 分支永远收不到。普通模式下 ↑/↓/Enter 又被 Vim 吃掉，补全候选既不能上下选也不能确认/关闭。
- 预期：有优先键位的浮层先处理 Esc；关闭后再由 Vim 处理下一次 Esc。
- 建议：把补全/预览的按键处理放在 Vim 之前；或 `vim_key_down` 在 `latex_completion_is_open()` / 补全开启 / `mermaid_preview` 存在时先让行。
- 置信度：medium-high（顺序确定；Mermaid 是否自带 Kit 焦点陷阱需窗口验证）；验证状态：代码路径核对。

### V-03【建议】Vim 命令行浮层没有焦点与层级守卫
- 位置：`src/editor/vim/command.rs:vim_cmdline_key_down`、`vim_close_cmdline_inner`；`src/editor/selection_toolbar.rs:selection_toolbar_anchor`。
- 触发：按 `:`/`/` 打开命令行后，点击正文或 AI 面板；或在可视选区里按 `:`。
- 实际：`vim.cmdline` 只由 Enter/Esc 清除，没有失焦订阅。点击别处后浮层仍留在底部，`vim_key_down` 仍优先把 Esc 等键交给命令行；同时选中工具栏的「别的浮层」判定没有列 `vim.cmdline`，可视模式下会压在命令行浮层上，点工具栏会直接改选区而不是执行命令。
- 预期：命令行只在输入框聚焦且未被其他浮层压制时接管按键；失焦/打开工具栏时收起。
- 建议：给命令行输入框加失焦关闭；`selection_toolbar_anchor` 补 `self.vim.cmdline.is_some()`。
- 置信度：high；验证状态：代码路径核对。

### V-04【必修】Vim 的单块编辑绕过 `write_back_block_source` 快路径，每次按键整篇序列化
- 位置：`src/editor/vim/operate.rs:vim_delete_within_block`、`vim_insert_raw_text`、`vim_replace_char_inner`、`vim_indent_range` 等直接改块后调用 `mark_dirty`；对照 `src/editor/window_state.rs:mark_dirty` / `mark_dirty_written_back`。
- 触发：大文档里连续 `x` / `dw` / `dd` / `~` / `r{char}` / 单块粘贴。
- 实际：`mark_dirty` → `finish_dirty` → `resync_buffer_from_projection`，在 `skip_next_resync` 未置位时执行 `document.markdown_text_with_block_spans` 整篇序列化（`source_serializations` 计数增加）。普通打字走 `on_block_changed` 的区间写回 + `mark_dirty_written_back`，一次按键 0 遍整篇序列化。Vim 的块内编辑事件虽会触发写回，但 `mark_dirty` 已经先付了整篇 O(文档) 的成本，随后的写回反而成了空写。
- 预期：单块编辑走 `write_back_block_source` + `mark_dirty_written_back`；结构变化才退回整篇。
- 建议：把单块 vim 变更统一收口到一个「写回本块后标记脏」的 helper；补 `x` 一次 `source_serializations` 增量为 0 的用例（与 `disabled_vim_key_path_returns_before_touching_the_document` 对称）。
- 置信度：high（路径确定；1 MiB 上的实际延迟未实测）；验证状态：代码路径核对。此项同时计入维度四。

### V-05【必修】`/` 搜索高亮被工作区搜索面板的开关条件挡住，`:noh` 只翻一个无人读的标志
- 位置：`src/editor/vim/command.rs:vim_apply_search_query` / `vim_clear_search_highlight_inner`；`src/editor/workspace/tree_sync.rs:sync_document_search_highlights`。
- 触发：用 `/two` 搜索并回车；随后执行 `:noh`。
- 实际：`sync_document_search_highlights` 的 `active` 条件是 `workspace.is_open && active_tab == Search && !query.is_empty()`。Vim 搜索只写 `search_query/search_scope`，不打开搜索面板，所以高亮通常根本不画；若用户恰好打开着搜索面板，`:noh` 只清 `document_active_range`，整篇命中仍会被 `all_hits` 重新高亮，`vim.hlsearch` 在非测试代码中没有任何读取点，是死状态。
- 预期：Vim `/` 在正文里显示命中；`:noh` 清除全部搜索高亮，且不影响后续 `n`。
- 建议：高亮判据把「Vim 搜索激活」纳入（或让 `hlsearch` 成为真正的开关）；`:noh` 时清空/跳过 `sync_document_search_highlights` 的普通命中。补一条窗口用例，断言 `:noh` 后块上的 `search_highlight_ranges` 为空。
- 置信度：high；验证状态：代码路径核对（现有测试只断言 `vim.hlsearch == false`，没有断言实际高亮）。

## 维度二 · 正确性、边界与并发

### V-06【必修】所有反向动作的操作符区间被写成倒序，`db`/`d0`/`d^`/`dF`/`d{`/`d(` 实际不删
- 位置：`src/editor/vim/operate.rs:vim_motion_range`（最终统一 `start: cursor, end: target`，只有 `Left/BackwardChars` 分支把倒序换回来）；`vim_delete_within_block` 里 `start.min(end)` 把倒序区间钳成空。
- 触发：`alpha beta` 光标在 `beta` 上按 `db`；`abcdef` 光标在第 3 列按 `d0`；`$dFa`；`d{`/`d(`。
- 实际：目标在光标左侧时 `start > end`；`vim_yank_quiet` 先往寄存器写入空串，`vim_delete_within_block` 把区间钳成 `target..target` 直接返回，正文不变。同理影响 `yb`、`cb`、`dge`、`gU b`、`g~0` 等所有「操作符 + 左向动作」组合。
- 预期：按 `MotionKind` 归一化方向后再构造 `VimRange`；左向动作返回 `start=target, end=cursor`（inclusive 动作用同样的端点规则）。
- 建议：在 `vim_motion_range` 统一做方向归一，避免每个调用方各自修；补 `db`、`d0`、`dF`、`d{` 用例（现有 `d_dollar_and_d_zero_clamp_to_the_line` 实际只测了 `d$`，没有按 `d0`）。
- 置信度：high；验证状态：代码路径核对。

### V-07【必修】块末单字符操作是空操作：`r{char}`、`~` 在每块最后一个字素上无效
- 位置：`src/editor/vim/operate.rs:vim_replace_char_inner`、`vim_swap_case_at_cursor`；`src/editor/vim/motion.rs:VimDocStream::next_grapheme`。
- 触发：`abc` 上按 `$ r z` 或 `$ ~`。
- 实际：`next_grapheme` 在块尾返回下一块起点（末块返回 None）。`r` 看到 `next.block_index != cursor.block_index` 直接 `return`；`~` 得到 `target == cursor`，区间为空，`vim_case_range` 提前返回。`R` 因有 `unwrap_or(text.len())` 兜底而正常，说明不是设计限制，而是漏了块尾分支。
- 预期：块内最后一字素仍是合法目标；块尾才进位/停住。
- 建议：与 `x` 的 `vim_motion_range` 一样，在块尾用 `hard_line_range(...).end` / `text.len()` 兜底；补 `$r`、`$~` 用例。
- 置信度：high；验证状态：代码路径核对。

### V-08【必修】字符可视端点算错：`v` 之后选区为空，`viw`/`vi"` 反而多选一到两个字素
- 位置：`src/editor/vim/visual.rs:vim_selection_as_range_inner` 与 `vim_extend_to_object_inner`；`src/editor/vim/operate.rs:vim_text_object_range`（对象返回的是排他终点）。
- 触发：`abc` 上按 `v d`；`alpha beta` 上按 `v i w d`；`"hello"` 上按 `v i " d`。
- 实际：`anchor == focus` 时字符分支直接返回空区间，所以 `v d`/`v y` 什么都不做（Vim 选中光标字素）。`viw` 先把焦点放到对象排他终点，再额外 `next_grapheme` 一次；`vim_selection_as_range` 又把焦点字素算进选区，于是 `viw` 在 `alpha beta` 上选中 `alpha b`，`d` 后剩 `eta beta`。
- 预期：进入可视时选区包含当前字素；文本对象直接落在对象区间上，只多/少一个字素都算错误。
- 建议：统一「focus 是最后包含字素」的口径：`vim_extend_to_object` 用 `prev_grapheme(range.end)`；`anchor == focus` 时按块尾/块内正常 +1 规则生成独占端。补 `v d`、`viw d`、`vi" d` 三条用例。
- 置信度：high；验证状态：代码路径核对（现有可视用例全部先移动了光标，未覆盖 `v` 直按操作符与 `viw`）。

### V-09【必修】块状可视 `o`/`O` 会把矩形选区塌成一列
- 位置：`src/editor/vim/visual.rs:vim_exchange_anchor_inner`、`vim_swap_block_column_inner`。
- 触发：`ctrl-v j l` 选出矩形后按 `o` 或 `O`。
- 实际：`O` 把 `visual_block_anchor_column` 设为当前焦点列后丢弃旧锚点列（`let _ = anchor_column`），光标不动，选区两端的列变成同一列；`o` 把锚点行/偏移换成旧焦点、锚点列换成旧锚点列，再把光标移到旧锚点，结果两列仍相同。矩形塌成单列。
- 预期：交换两个角后矩形面积不变（Vim 的 `o`/`O` 语义）。
- 建议：块状 `O` 需要同时把光标水平移到旧锚点列并记住旧焦点列；`o` 应按「新锚点列 = 旧焦点列、新焦点列 = 旧锚点列」重算。补一条块状可视交换后 `d` 的用例。
- 置信度：high；验证状态：代码路径核对（现有 `o` 用例是字符可视，块状没有）。

### V-10【必修】块状可视缩进/出缩进错误，并偷偷覆盖寄存器与系统剪贴板
- 位置：`src/editor/vim/operate.rs:vim_apply_block_operator`。
- 触发：代码块里 `ctrl-v j l >` 或 `ctrl-v j l <`；块状可视里按 `u`/`U`/`~`/`>`。
- 实际：`Operator::Indent` 按从上到下的顺序在每个 `range.start` 插入 4 个空格；第一次插入后同块后续行的偏移已右移，后面的插入落在旧偏移处，行首被插进空格串中间。`Operator::Outdent` 插入空串，等于什么都不做。另：函数在分派操作符前无条件 `registers.write(register, ...)`，所以缩进/大小写操作也会覆盖无名寄存器，`use_system_clipboard=true` 时还会把选中的正文写进系统剪贴板。
- 预期：块状缩进逐行按当前偏移（逆序或先算 delta）落笔；出缩进真正去掉一个缩进级；非 yank/delete 操作不碰寄存器。
- 建议：缩进按 `ranges.iter().rev()`；出缩进复用文档的 outdent 逻辑；把寄存器写入移到 `Delete/Yank/Change` 分支内。补块状 `>` 多行与 `<` 用例。
- 置信度：high；验证状态：代码路径核对。

### V-11【必修】行级 `>>`/`>j`/可视 `>` 只缩进「块」，没有按选中的硬行缩进；代码块 `<<` 是空操作
- 位置：`src/editor/vim/operate.rs:vim_indent_range`；`src/components/block/interactions.rs:on_indent_block` / `on_outdent_block`。
- 触发：多硬行段落第一行按 `2 >>`；代码块里 `>>` 或 `<<`；`V j >`。
- 实际：`vim_lines_range` 给出的是硬行区间，但 `vim_indent_range` 只遍历块下标，段落用 `block.cursor_line_display_range()`（永远是块当前光标那一行），所以 `2>>` 只动当前行；代码块调用 `on_indent_block`，它在光标处插入 4 空格（不是行首），且只动一个点；`on_outdent_block` 只处理列表缩进，代码块 `<<` 什么都不做。
- 预期：行级操作对区间覆盖的每一条硬行在行首增删一个缩进级。
- 建议：把行级缩进改成按 `VimRange` 内的硬行区间逐行处理，代码块/段落共用同一处「行首增删」判据，列表块再交给现有层级动作。补 `2>>`（同块两行）、代码块 `>>`/`<<`、`V j >` 用例。
- 置信度：high；验证状态：代码路径核对（现有两条缩进用例都是单行段落）。

### V-12【必修】脏文档 `:wq` / `:x` / `ZZ` 不保存，直接弹「未保存」确认框
- 位置：`src/editor/vim/command.rs:vim_execute_command`、`vim_save_and_close`；`src/editor/window_state.rs:request_save_document`；`src/editor/workspace/tabs.rs:close_workspace_tabs`。
- 触发：有未保存修改时输入 `:wq`、`:x` 或按 `ZZ`。
- 实际：`request_save_document` 只置 `pending_save`，真正落盘要等下一帧 `sync_pending_save`；紧接着 `vim_close_current_tab` 里的 `snapshot_current_document` 看到 `dirty = true`，走未保存确认模态。用户点「不保存」时这次 `:wq` 就变成丢弃；点「保存」也要多一次交互，且切换文档可能清掉排队中的 `pending_save`。
- 预期：写盘成功后静默关闭，失败则留在文档并报错（Vim 的 `:wq`）。
- 建议：复用已有的「先保存再关闭」链路（`finish_close_workspace_tabs(..., save_first=true)` / `pending_tab_close_after_save`），不要在同一个事件里「排队保存 + 立即关」。
- 置信度：high；验证状态：代码路径核对（Vim 测试没有 `wq`/`ZZ` 用例）。

### V-13【必修】宏自引用/互相引用造成无界递归，进程栈溢出
- 位置：`src/editor/vim.rs:vim_replay_macro`、`vim_replay_record`。
- 触发：`q a @ a q` 录制后再按 `@ a`；或两个宏互相 `@`。
- 实际：`guard_counter` 是每次 `vim_replay_macro` 调用的局部变量，`vim.replaying` 只用于阻止「再次录制」，入口没有「正在重放哪个宏」的检查。`@a` 重放到 `@`/`a` 时递归进入 `vim_replay_macro`，`catch_unwind` 接不住栈溢出（SIGSEGV/abort），`resume_unwind` 也走不到。
- 预期：像 Vim 的 E223 一样拒绝递归宏，保留进程与文档。
- 建议：`VimState` 增加 `replaying_macros: Vec<char>`（或深度计数），入口发现同名正在重放立即返回；宏栈用 RAII 弹出，避免 panic/提前 return 泄漏。补一条自引用宏用例。
- 置信度：high；验证状态：代码路径核对。

### V-14【建议】`G` 落最后一个块的首行，不是文档最后一行；`H`/`M`/`L` 按文档块下标算，不按视口
- 位置：`src/editor/vim/motion.rs:vim_document_line_landing`、`vim_screen_line`。
- 触发：末块是多行段落/代码块时按 `G`；长块（单块占满视口）按 `H`/`M`/`L`。
- 实际：`DocEnd` 取最后一个导航块的第一行首个非空白；`ScreenLine` 用 `entities.len()` 的首/中/末块，不读行计划或滚动偏移。长段落里 `M`/`L` 与当前视口无关，`H` 的计数是「往下数块」而不是「往下数行」。
- 预期：`G` 落最后一行行首非空白；`H/M/L` 落视口首/中/末可见行的行首。

- **undo 组被中途收尾**：`vim_merge_blocks` 内部调用 `finalize_pending_undo_capture`，而 `J`/跨块删除外层也开着一个组；可能把一次 `J` 拆成两步撤销。需要一条「J 后一次 u 恢复原样」的用例确认。

- **`vim_search_match_vim_range_inner` 的终点映射**：`source_to_content.get(buffer_range.end - base)` 在命中恰好到块尾时是否越界，取决于映射表是否含端点；`gn` 的块尾用例可验证。
- **`vim_surround` 的 padding**：`ys(` 插入 `( ... )`，`ds(` 只删定界符不删内边空格；与 vim-surround 的行为有差异。
- **`:wq` 的平台差异**：未在 macOS/Windows 实机确认未保存模态的按钮顺序与焦点行为；核心时序问题与平台无关。
- **`vim_finish_insert_session` 的块状 I/A undo**：多行复制是直接 `replace_text_in_visible_range`，虽会经 `Changed` 打开撤销组，但没有独立用例；建议补「块状 I 输入后一次 u 全部还原」。

## 功能缺口与实用需求（用户点名可提）

以下不算缺陷分级，按「Vim 用户会立刻缺」到「锦上添花」排序：

1. **`:e` / `:w!` / `:qall` / `:wa`**：目前只有 `:w`、`:wq`、`:x`、`:q`、`:q!`、`:noh`、`:N`、`:s`。打开/重载/批量关闭是日常动作。
2. **搜索历史与 `n` 的跨块高亮**：`/` 没有历史（↑ 不能取上次查询），命中高亮还依赖搜索面板；建议把 Vim 搜索做成独立的高亮层。
3. **`gp`/`gP`、`g;`/`g,`、`gi` 的精确落点**：`gp` 保留寄存器行级标记，`g;` 回到上次修改处，是编辑长文的高频动作。
4. **路径/窗口类对象**：`af`/`ic`（函数/类）、`ctrl-w` 窗格前缀、`gt`/`gT` 标签页；仓库已有文件树与分屏，接到现有命令注册表即可。
5. **可视块 `I`/`A` 的多行文本与撤销**：现在只复制单行字符，且 Tab/Enter 不参与；补齐后才是可用的列编辑。
6. **`:g/pattern/command` 与 `:v`**：批量删除/替换章节、按模式操作行，是 Vim 的核心生产力之一。
7. **宏与 `.` 的 IME 支持**：中文作者目前无法用 `.` 重放输入；建议用文本 diff 生成重放素材（同时修复 V-27）。
8. **状态栏的模式/寄存器提示可选显示**：例如显示当前寄存器、搜索方向、宏录制状态；Vim 用户靠这些确认状态。
9. **Vim 开关的快捷键与命令面板一致性**：`toggle_vim_mode` 在命令注册表和菜单里，但 `components/actions.rs:SHORTCUT_DEFINITIONS` 没有条目，快捷键页也无法绑定（见 AI 侧同类的四入口检查）。
10. **`use_system_clipboard` 的文档与行为统一**：要么 `+` 永远直通系统剪贴板，要么明确「关掉就完全禁用」，不要出现读得到、写不进的半开状态。

### A-20【必修】排除项与资料范围只按字面 id 判定，符号链接/路径别名可绕过
- 位置：`src/ai/workspace.rs:AiWorkspace::snapshot` / `resolve` / `set_scope` / `is_excluded`。
- 触发：工作区内存在 `alias.md -> private/secret.md`（或 `aliasdir -> private/`），`private/` 已被用户排除；模型或用户用 `@alias.md`、`read_document("aliasdir/secret.md")` 访问。

- 置信度：high（canonicalize 跟随符号链接、`resolve` 不再复核排除项，代码路径确定）；验证状态：代码路径核对，未跑文件系统用例。

## 未验证 / 值得一看（AI）

- **手动停止的 tool_use 配对**：已核对 yoagent 0.25.7，取消会把未执行的 tool call 回答成 cancelled result，`mark_cancelled` 只在已有 assistant 消息时补停止标记；未发现悬空的 `tool_use`，暂不列为缺陷。
- **磁盘快照的 `(mtime, len)` 判据**：`AiWorkspace::snapshot` 用修改时间 + 长度判断缓存是否失效；在时间戳精度较粗的文件系统上，同长度快速改写可能命中旧快照。需要一条可控 mtime 的用例确认。
- **代码/表格的逐条修改映射**：`inline_review::tracked_document` 依赖两个编辑器的块边界；代码文件按 Markdown 渲染（A-09）以及表格块无文本元素时，逐条接受的高亮范围是否仍准确，未跑用例。
- **会话恢复体积**：`SavedSession::load_at` 允许 256 MB 的会话文件，历史里可能包含整篇文档与工具输出；恢复在后台执行，但 UI 侧反序列化后的内存峰值未评估。
- **重试与指令快照**：失败重试沿用首次发送时的 `prompt_profile`，与「每个任务首次发送固定前缀」一致；如果产品希望重试用新设置，需要显式设计，目前不算缺陷。
- **`test_connection` 的副作用**：连接测试会真实发起一次带工具调用的请求，失败原因可能包含端点返回的原始报文；确认错误文案没有把 Key 带进界面日志。

## 功能缺口与实用需求（AI）

1. **自定义指令真正可用**：补「使用 / 追加到草稿」与预览（A-01）；否则这个面板只能当笔记。
2. **`@` 补全与工作区搜索**：现在资料面板只列已打开标签，手输路径要求完全正确；建议支持输入 `@` 后搜索文件名/目录、引用目录展开、已选引用以 chip 形式可删。
3. **单任务切换连接/模型**：设置里改默认连接会影响后续任务；建议在任务标题栏提供本次使用的连接/模型，并支持「换个模型重试」。
4. **预算可见**：展示本轮输入/输出 token、上下文占用与压缩事件；在接近预算时提示缩小资料范围。`RunOutput` 已经收集了 token，只是没有界面。
5. **继续与编辑**：长度截断/手动停止后提供「继续」；允许编辑并重发上一条用户消息，而不是只能从头重试。
6. **草稿与历史管理**：输入草稿随会话持久化（目前只在内存里）；历史支持重命名、置顶、搜索与导出，避免只能按时间找。
7. **多模态输入**：截图、图片、PDF 拖入对话作为上下文；对 Markdown 编辑器来说，截图解释公式/排版是高频需求。
8. **密钥与网络提示**：Keychain/凭据管理器；非本机 HTTP 明确警告（A-18）；可配置代理。
9. **发送前边界预览**：列出本轮会发给模型的文档与片段，支持一键排除敏感文件；配合 A-17 的默认拒绝集。
10. **代码文档支持**：代码标签可打开助手、审阅按源码显示（A-08/A-09）；或者明确只支持 Markdown 并在工具层拒绝代码文件。
11. **Skill 激活可视化**：Use 后在输入区显示激活的 Skill，发送前校验 id；支持本轮临时禁用/启用。
12. **自由对话入口补齐**：正文右键与选中工具栏目前只有五个快捷指令，想「问 AI」需要记 `⌘J`；建议在 AI 二级菜单底部加「打开对话」。
13. **只读状态提示**：阅读任务/只读文档中明确标注「仅建议，不可应用」，并禁用容易让用户误以为能改的入口。
14. **会话清理**：`ai/sessions/` 没有保留策略与占用展示；建议提供按工作区清理、单条删除与总大小提示。
