## 维度一 · 仓库既有不变量与 GPUI 契约

### 【必修】A1 `src/net/update/install.rs:MACOS_HELPER` — 更新安装把其他实例硬杀，其他窗口里未保存的正文直接丢

- **问题**：同一批在 Windows 侧定下「请退不退就放弃这趟更新」的策略，macOS 侧执行的是「请退 0.5 秒后强杀」。
- **触发条件**：`open -n -A Velora`（或从终端再起一个进程、另一份副本）里那扇窗口正在编辑且未保存 → 在当前窗口点「更新」。安装前 app 只调 `save_dirty_workspace_documents_and_close` 保住**本进程**的正文；helper 在 `/bin/kill -0` 通过后立刻 `killall -TERM velora` → `sleep 0.5` → `killall -KILL velora`（install.rs:173–179）。SIGTERM 的默认处置就是终止，GPUI 不会在信号里跑窗口关闭流程，那句「还有未保存的修改」根本弹不出来。`killall` 按进程名匹配，`/usr/local/bin/velora` 指向同一份可执行文件，终端里跑着的 `velora` 进程一起被杀。
- **预期 vs 实际**：预期同 Windows（`WINDOWS_HELPER` 的 `$closeTimeoutSeconds = 30` + `throw '还有其他 Velora 窗口未关闭'`）；实际 0.5 秒后无条件 `-KILL`。
- **建议修法**：`killall -TERM` 后轮询 `killall -0 velora` 并设超时上限，超时就不装、走已有的 `install_error` + 拉起 `previous_executable` 那条失败支路。既有测试 `MACOS_HELPER.contains("/usr/bin/killall -KILL")` 钉的是当前形状，改时要一并改。
- **置信度**：high — **验证状态**：主线程读 install.rs 与新加的三条 helper 断言核对过，两个平台的策略文本逐条比对。

### 【必修】A2 `src/editor/status_bar.rs:render_custom_button` — 自定义按钮是「只画不派发」的第五入口，`action_id` 全仓零消费

- **问题**：违反不变量 11（一个动作只有一处实现，四条入口汇到同一函数）。607f692 把按钮接进了运行时镜像与偏好保存，派发那一半没接。
- **触发条件**：在 `config.toml` 的 `[status_bar] custom_buttons` 里配一条 `{ id=…, label=…, action_id="select_document" }` → 重启 → 状态栏出现该按钮（`.cursor_pointer()` 明示可点）→ 点击无反应。
- **预期 vs 实际**：预期按 `action_id` 从 `src/commands.rs:COMMANDS` 查出同一份判据与处理函数；实际函数体只有 `.on_hover(cx.listener(…))`，没有 `on_click`/`dispatch_action`，也没有可用判定。全仓 `action_id` 只出现在 `config/preferences.rs` 的字段定义与 `preferences/persistence.rs` 的解析/回写，产品代码零消费。
- **建议修法**：补 `.on_click`，按 `button.action_id` 取 `CommandSpec::boxed_action()` 后 `window.dispatch_action`，与 `command_palette.rs:run_palette_command` 同一收口；查不到 id 就不渲染该按钮并在启动时 `log::warn!` 一次；可用判定也接进 `COMMANDS` 那一份。
- **置信度**：high — **验证状态**：主线程核对（grep `render_custom_button` 函数体 + 全仓 `action_id` 消费点）。

### 【必修】A3 `src/editor/command_palette.rs:on_command_palette_key_down` — 组合期间的回车被执行成命令

- **问题**：新 `"enter"` 分支不判 `state.marked_range`；`src/editor/workspace/tree_edit.rs:on_workspace_name_key_down` 里已有那条「组合期间不吃确认键」判据（`if edit.pending || edit.marked_range.is_some() { return; }`），这条新入口没借（不变量 9 + 11）。
- **触发条件**：⌘⇧P 打开面板 → 拼音输入「打字机」（`marked_range` 有值）→ 按回车提交候选词 → 面板收起并执行列表第 0 行。macOS 侧 `vendor/gpui/src/platform/mac/window.rs:1716` 在 `is_composing` 时把键交给 IME，提交后 `do_command_by_selector`（window.rs:2310–2323）用同一颗 keystroke 合成一次 `KeyDown("enter")` 送进应用。`overlay_input.rs:228` 刚在提交前把 `selected` 重置为 0，所以执行的是新过滤结果的第一条。

- **置信度**：high — **验证状态**：子代理逐层核到 vendored gpui 的键盘路由；主线程未独立复现 IME 派发（需要真机中文输入法），建议按技能 `velora-tdd` 先用 `TestAppContext` 的 marked text 事件复现。

## 维度三 · 安全

### 【必修】C1 `vendor/gpui/src/platform/windows/clipboard.rs:read_html_from_clipboard` — 外部不可信剪贴板可打崩应用，且无条件在前景线程全量复制

- **问题**（三点合一）：
  1. **无大小上限**：`with_best_match_format` 的成功分支对文本/图片/文件**任一**味道都会调 `read_html_from_clipboard`；`from_raw_parts(ptr, size).to_vec()` 整份拷进堆，随后 `cf_html_fragment` 的 `from_utf8_lossy(..).to_string()` 再拷两份，消费侧 `maybe_markdown_from_clipboard` 又 `to_string()` 一份并交 html5ever 建 DOM。从浏览器复制整页文章（HTML Format 载荷几 MB 到几十 MB）后按 ⌘V：UI 线程一次性 4~5 份多 MB 拷贝 + 一次全量 DOM 往返，峰值内存约为载荷的 8~12 倍，窗口无响应数秒。
  2. **`GlobalLock` 返回值未判 NULL**：`with_clipboard_data`（同文件:378）只判了 `GetClipboardData(..).ok()?`；`size > 0` 时 `from_raw_parts(null, size)` 是未定义行为，而大载荷下正是最容易锁失败的一档。
  3. 编码未判定就 `from_utf8_lossy`（见建议 C2）。
- **触发条件**：Windows 上从任意网页复制整页 → ⌘V。
- **建议修法**：读之前先 `GlobalSize` 上限闸门（例如 2 MiB，超过就当没有 HTML 味道并 `log::warn!`）；把 `[start..end)` 的偏移解析挪进 gpui 侧、只拷需要的那段；`with_clipboard_data` 里 `if data_ptr.is_null() { return None; }`。
- **置信度**：high — **验证状态**：子代理逐行核到 `with_clipboard_data` 与 `cf_html_fragment`；崩溃面（NULL）需 Windows 实测确认，无上限与前景线程可直接照读代码复现。

### 【建议】C2 `vendor/gpui/src/platform/cf_html.rs:cf_html_fragment` — 载荷编码未判定就 `from_utf8_lossy`，乱码进文档而不是回退纯文本味道

- 从中文版 Word / 写字板复制表格（CF_HTML 按声明编码写多字节）→ `payload[start..end]` 不是合法 UTF-8 → 每个非法序列换成 U+FFFD → `fragment.is_empty()` 过不了 → 返回 `Some(乱码)` → `html_to_markdown_or` 拿到「看起来有结构」的乱码串，`unmarkdown(converted) == unmarkdown(plain)` 那条回退也被乱码破坏 → 乱码写进缓冲区并可被保存回文件。
- 不变量 5 的口径是「判不出来的字节拒绝，不以乱码呈现」，这里应当同样：解不开就当没有这个味道，让粘贴用同一次复制的纯文本味道。
- **建议修法**：`String::from_utf8_lossy` 换 `String::from_utf8(&payload[start..end]).ok()?`；要真支持多字节编码再单独按 `charset=` 声明解码。
- **置信度**：medium — **验证状态**：子代理核代码形状；未用真实 Word 载荷复现。

### 无必修：本批未引入 XSS 汇（复核结论）

- 落单标签走 `escape_html`；配对那支仍过 `sanitize_inline_html_open_for_export → has_dangerous_attrs`（`html/parse.rs:390`，`on*` 前缀 + `is_safe_export_url` 拦 `javascript:`/`data:`）。
- `html_paste::with_table_headers` 只把 DOM 往返结果喂给 htmd（Pure 模式 + `skip_tags` 覆盖 script/style/head/meta/link），产出是 Markdown 文本，不是可执行 HTML。

- 更新器下载侧校验完备：`net/update.rs:validate_package` + `receive_package` 强制 https + `github.com` host + `releases/download/` 前缀 + sha256 摘要 + magic + 声明大小；失败上报走 `show_async_message_modal`，未新增系统原生弹窗（不变量 12 合规；NSIS 里的 `MessageBox`/`taskkill` 属安装器层，不在该门禁管辖）。

- `cf_html.rs` 资源所有权：纯 Rust 切片实现，无 `CFRelease`/句柄，不存在泄漏路径；越界靠 `start.min(len)` / `end.min(len)` + `start >= end` 挡住，不 panic。
