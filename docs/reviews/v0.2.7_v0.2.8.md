## 维度一 · 仓库既有不变量与 GPUI 契约

### 【必修】A1 `src/editor/history.rs:prepare_block_undo_capture` — 首行前缀判据的第二份实现，三处与原件分叉

- **问题**：新加的 165 行函数把 `src/editor/source_mapping.rs:measured_block_line_prefixes`（内含 `measured_block_prefix`）那条「每行让开几字节」的判据重抄一遍，另起一套 `prefixes/file_lens` 记账与 `measured_block_prefix` 兜底加 `.min(text.len())` 夹逼。
- **触发条件**：在带容器记号的块（列表项 / 标题 / 引用、多行、非规范写法）里打字后撤销；或选中整块文字做多行粘贴。
- **预期 vs 实际**：预期撤销落点与粘贴替换范围与跨块路径同一口径；实际三处分叉——① 原件在 `model_indent > file_indent` 时返回 `None`（整块退回按模型拼），抄本用 `indentation.saturating_position()` 静默钳零；② 原件续行剥 `quote_depth + is_quote` 两层，抄本只剥 `quote_depth`；③ 原件由调用方传实测 `list_dedent`，抄本写死 `render_depth * 2`（正是 `measured_block_prefix` 注释点名的「四空格嵌套列表打一个字，字节进了父项那一行」）。表现：粘贴 `- 甲` 全选贴两行 → `乙`/`丙` 掉出列表。
- **建议修法**：`prepare_block_undo_capture` 复用 `measured_block_line_prefixes`（必要时提 `pub(super)`）；端点换算一律走 `selection.rs:mapping_source_range_endpoint`（`capture_source_selection_snapshot`、`prepare_block_undo_capture`、`events/paste.rs` 三处目前各手写 `mapping.content_to_source[..] + full_source_range.start`）；抄本里的 `saturating_sub` 换成「算不出就放弃这条路」。
- **置信度**：high（重复与分叉是代码事实；用户可见程度 medium）
- **验证状态**：已核。主线程确认两处函数并存且 history 侧自成一套路；子代理逐行对照 `history.rs` 与 `source_mapping.rs:measured_block_line_prefixes`。

### 【必修】A3 `src/components/block/interactions.rs:on_newline` — 「文档级选区是否生效」两套判据

## 维度二 · 正确性、边界与并发

### 【必修】B1 `src/editor/events/quotes.rs:block_event_clears_cross_block_selection` — 换格不清选区，下一键写回旧格子

- **问题**：清除清单包含 `RequestIndent`/`RequestDelete`/`Changed` 等 16 项，**不含** `RequestTableCellMoveHorizontal`/`RequestTableCellMoveVertical`；`interactions.rs:on_newline` 的表格分支只发换格事件并 `return`，`table_nav.rs:focus_table_cell_position` 也只 `focus_block`。而 `selection.rs:sync_document_selection_ownership` 会把 `table_text_selection` 生效时置全局标志为 `true`。
- **触发条件**：拖选跨格（`table_text_selection = Some`）→ 在锚点格按 Enter（或 Tab）→ 焦点换到新格 → 打字。
- **预期 vs 实际**：预期在新格插入；实际 `input.rs` 走 `has_document_selection()` → `replace_table_text_selection_with_text` 删的是**旧格子**那几段字节、字落在旧选区起点，新格什么都没收到，旧高亮还留着。v0.2.7 按局部字段判不会劫持新格输入——**本批 72b881b 引入的回归**。
- **建议修法**：把两个换格事件列入清除清单（或在 `focus_table_cell_position` 里调 `clear_cross_block_selection`）。
- **置信度**：high
- **验证状态**：已核。读到清除清单全文（确无换格两项）、`sync_document_selection_ownership` 里 `table_text_selection` 参与置位、`table_nav.rs` 换格两支只移焦点。

### 【必修】B2 `src/components/block/runtime/normalize.rs:apply_link_projection_edit` — 漏发 `CompositionChanged`，撤销组悬开

- **问题**：同批的 `apply_title_edit` 在 marked 状态变化时发 `cx.emit(BlockEvent::CompositionChanged)`；链接投影这条早退分支把 `self.marked_range` 置 `None` 后只按「kind 或 title 变了」发 `Changed` 就 `return`。标题没变 → 既无 `Changed` 也无 `CompositionChanged`；随后 GPUI 的 `unmark_text` 取到 `None`（`changed == false`）也不发 → `Editor::finish_ime_composition` 永不执行。
- **触发条件**：段落含 `[中](url)`（`!run.link.is_source_preserving()`），输入法在标签内打同一个字后原样上屏（提交文本 = 已 marked 文本）。
- **预期 vs 实际**：预期与 `ime_lifecycle.rs:core_repair_same_text_ime_commit_separates_following_typing` 同语义；实际 `Editor::pending_undo_capture` 一直开着（`prepare_undo_capture`/`prepare_block_undo_capture` 开头都有 `pending.is_some()` 即 return），下一次编辑的字节并进这个 `ImeCompositionCommit` 组、组内选区是组合开始前的旧现场 → 一次撤销退两步、落点错位；本批同时修的 autosave 恢复也没触发。
- **建议修法**：把「marked 状态变化」收成一个 `fn set_marked_range(&mut self, …, cx)` 在唯一出口发信号。现网同型静默清 marked 的点还有 `runtime/text_ops.rs`、`interactions.rs`、`events.rs`、`runtime/display_cache.rs` 共约十处，收编时一并。
- **置信度**：high
- **验证状态**：已核（两支对照读到：`apply_link_projection_edit` 无 `CompositionChanged`，`apply_title_edit` 有）。

### 【必修】B3 `src/editor/workspace/tabs.rs:finish_close_workspace_tabs` — 用弹框前的快照落盘并清脏标记

- **问题**：`save_first` 分支全程只读 `closing: &[WorkspaceDocumentTab]` 里的 `tab.markdown`/`tab.file_version`，不读活动文档的当前缓冲区；写成功后 `mark_workspace_document_saved` + `self.document_dirty = false` + `remove_recovery_snapshot(tab.recovery_id)`，`active_was_closed` 分支还把 `self.file_path` 置 `None`。同一入口也没有其余四个保存入口都有的 `has_marked_document_text` 检查。
- **触发条件**：活动文档脏 → 点标签 X（或关闭其它标签把活动文档一起带走）→ `close_workspace_tabs` 先 `snapshot_current_document` 再克隆 `closing` → 弹「保存并关闭」模态。`modal.rs` 明确写着「模态自身不抢焦点」（抢焦点会跟编辑器的焦点岛打架），拦截器只吃 Enter/Esc，**所以框开着时用户还能继续打字** → 点「保存并关闭」。
- **预期 vs 实际**：预期写当前缓冲区内容并保留脏标记/恢复快照；实际磁盘 = 弹框前的旧文本，缓冲区 = 新文本，脏标记被清、恢复快照被删、圆点消失、autosave 因不脏不再排任务 → 退出或崩溃即丢字。（若期间自动保存恰好落盘，则变成假「检测到外部修改」冲突并阻止关闭。）
- **建议修法**：活动文档改走 `save_to_existing_path`，或 `StagedDocumentWrite::prepare + commit_checked` 并在提交前用 `workspace_save_snapshot_is_current(recovery_id, path, text)` 与 `document_save_identity()` 双重判据；入口补 `has_marked_document_text` → 延后到组合结束。
- **置信度**：high
- **验证状态**：已核。读到该函数写盘与记账全程不读 buffer、`closing` 在弹框前克隆、`modal.rs` 不抢焦点的注释；对照 7f77fad 给另两条批量入口补的 `workspace_save_snapshot_is_current` 闸门（`persistence.rs` 两处）唯独没给这里。

### 【必修】B4 `src/components/block/render/parts.rs:cached_table_column_layout` — 列宽缓存键缺正文字体族

- **问题**：`font_fingerprint` 只混 `window.text_style().font()`（family/weight/style）+ `fonts.code_family`/`code_size`，`theme_fingerprint` 只有标量；而正文渲染字体是 `editor_text_font(body_font_family)`（`element/text_element.rs` 的 `font_fingerprint` 明确含 `markdown_family`，可证渲染口径在正文字体）。

- **预期 vs 实际**：预期正文字体族变化即换代重测列宽；实际 memo 全键命中、不重测，列宽按旧字体钉住、渲染 mid-word 折行——正是 bf36b62 提交动机里的症状，本笔只补了代码字体与窗口字体两条轴。

- **置信度**：high（缓存键缺轴确证；measure 取哪一份字体待红测确认）
- **验证状态**：已核缓存键覆盖，读到 memo 比较的五个条件项与 `measure_cell_preferred_width` 签名。

### 【必修】B5 `src/editor/persistence.rs:schedule_autosave` 提交循环 — 冲突框被顶掉，自动保存永久停摆

## 维度三 · 安全

无【必修】。6f7253a 的配对栈逐条核过：开标签属性经 html5ever DOM 解码后走 `has_dangerous_attrs` + `sanitized_open_tag`（与既有全量净化器同源）；`on*`、`href/src/action/formaction/xlink:href`（含实体混淆 `&#x73;`、制表符/NUL 变形）仍被拒并转义成 `vlt-raw-html`；未配对闭标签丢弃、块结束按栈收齐且内层先闭；`<script>/<style>/<plaintext>` 等 raw-text 标签不在白名单，落 `&lt;` 转义；`<head>/<body>` 展开陷阱被 `nodes.len() != 1` 挡住；导出模板自带 CSP `default-src 'none'` 兜底。**blank-group 改走 `walk_group` 实际堵上了 v0.2.7 的一处真 XSS**（纯 InlineHtml 段落原文直出）。

`options.mode(0o600)` 且目标不存在时无权限可继承。触发：另存为到新路径、拖入替换首次落盘、查找替换首次创建、关闭标签保存新建文件。预期：已存在文件保留原 mode（本笔目标），新文件沿用系统 umask；实际新文档只有 owner 可读，共享目录/被其它用户或进程读的笔记失效，而同目录导出的 HTML（`export/mod.rs` 用 `fs::write`）仍是 0644，两种口径并存。修法：目标不存在时按 `0o666 & ~umask`，只在目标存在时继承其 mode。置信度 medium。

UI 对 `parse_html_attrs` 的**字面原值**跑 `has_dangerous_attrs`（`href="java&#x73;cript:x"` 实体不解码 → 判 safe），导出对 **DOM 解码值**判 dangerous（`html/parse.rs` 注释自证）。当前无危害（UI 侧 `<a>` 的 href 不可点、`tag_style == extra_style` 时整体退回字面），但将来给 HTML 锚点接触发器时，UI 那份就是绕过实体解码的那份。修法：把「URL 属性先 DOM 解码再判」写进 `has_dangerous_attrs` 的调用契约。置信度 medium。

## 维度四 · 性能与效率

### 【必修】D1 `src/editor/document/blocks.rs:collect_list_blocks` — 列表子块每个都重建 `MarkdownLookahead`（平方扫描漏网）

- **问题**：两处 `&MarkdownLookahead::new(&anchor_dedented)` 都在 `while body_index < item_end` 循环体内——每个子块对**该项剩余区间**重扫两遍（`MarkdownLookahead::new` 是正反两趟逐字符扫描），并各分配一个 `Vec`（n+1）与一个 HashMap。

- **建议修法**：进入该项循环前按项正文区间建一次索引、带 `line_base` 复用（照 root chunk 那样共享 `Arc`）；工作量回归把列表项这一族也计入 `scan_probe`。
- **置信度**：high
- **验证状态**：已核两处构造点在循环体内。`import_round_trip.rs` 新增的工作量用例只覆盖 3000 段纯段落，无列表夹具——**这条不会被现有门禁抓到**。

### 【建议】D2 `src/editor/source_mapping.rs:push_line_prefixed_inline_mapping` / `push_table_row_mappings` — 每次 mapping 重建对块原文做完整行内解析 + 序列化 + 两趟 align

`perf_budgets.rs` 的实测口径是一次按键 3 次按块重建（`delta.1 <= 3`）；渲染态段落/标题/列表/引用/提示框/脚注首子块都走 `parse_inline = true`，表格 `push_table_mappings` 对**每一格**调 `InlineSourceOffsetMap::parse`（旧实现这里只是一条长度对账 + `(0..=len).collect()`）。块内成本随字节数 × 每帧 3 次，还额外产生 4 份 `Vec<usize>`。墙钟闸门只数遍数、不测块内耗时，表格也没闸门。修法：`original_content == content_markdown` 时直接吃恒等表；更彻底是复用导入期那一次解析——`BlockRecord` 存住 source↔markdown 表、按 `document_revision` 失效。置信度 high。

### 【建议】D3 `src/editor/persistence.rs:StagedDocumentWrite::commit_checked` — 每次保存整篇读盘 + 解码 + 哈希三遍，其中一遍在前台线程

`commit_checked` 在 `editor.update(cx, …)` 闭包内执行 `verify_file_version → encoding::load_document`（`fs::read` + `detect_and_decode` + `file_content_version` 两次全文 `replace` + SipHash）。自动保存一趟里同一文件还被后台 `verify_file_version` 连查两次（后一次的 `disk_raw` 直接丢弃），手动保存则是两次前台整篇读；N 个脏标签就是 N 次主线程整篇读（10 MiB 量级几十 ms/篇）。`performance.md` 与 `perf_budgets.rs` 没有保存路径闸门，所以无人报警。修法：删掉 prepare 之后那次后台 `verify_file_version`（已被 `commit_checked` 完全覆盖）；提交前现势校验改「`stat` mtime+size 未变即 rename，变了才重读重算」，或把校验留在后台线程。置信度 high。

### 【建议】D4 `src/editor/history.rs:finish_ime_composition` → `history_group_is_noop` → `buffer.clone()`

每次组合结束（含取消）都调它，而它 `let mut probe = buffer.clone()`——`TextBuffer { chunks: Vec<Chunk{ text: String, .. }> }` 是**深拷贝全文**。中文输入每上屏一个词就 O(文档) 一次前台拷贝 + 整组重放（`buffer.rs` 注释里「10 MiB 一次按键 6 秒」就是这类账）。修法：先做廉价预判（组内 `net_byte_delta == 0 且 edits.len() % 2 == 0` 才 clone），或限定 `byte_len` 阈值。置信度 medium。

### 【建议】D5 `src/components/block/runtime/cursor.rs:prepare_undo_capture` — 每键在 Block 侧构造 `BlockUndoSelection`

`Lines` 分支两次 `display_text()` 并对前缀做 `matches('\n').count()` 全文扫；`Inline` 分支 `record.title_markdown()`（memo 命中也要 clone 整块 String）+ `split('\n').map(leading_blank_bytes).collect()` + `source_line_prefixes.clone()`，再克隆进事件。Editor 端 `pending_undo_capture.is_some()` 时全部白算；本批新加的 8 个删除路径一次删除调两遍（`prepare` + `replace_text_in_range` 内再一次）。修法：给 Block 一个「编辑器是否有开组需求」的轻量标志（`has_pending` 也做成共享 `Cell`）。置信度 medium。

### 【建议】D6 `src/editor/selection.rs:cross_block_source_range_for_normalized` — 复制/剪切路径仍 `visible_blocks().to_vec()`

a0940d0 把高亮同步限定到选区切片（已验证 `sync_cross_block_selection_visuals`/`clear_cross_block_selection_visuals`/`cross_block_covered_table_cells` 均按索引切片，`selection_visual_visits` 判据成立），但该函数每次复制仍克隆整根可见列表（10 MiB 文档 ≈16 万个 `Entity` 克隆），且 `cross_block_selected_markdown` 与 `cross_block_source_selection_snapshot` 各调一次。「局部选区操作限定文档范围」对复制路径没做实。修法：`visible_blocks()` 借切片即可。置信度 medium。

### 【存疑】D7 `src/editor/buffer.rs:same_content` — 撤销组收尾多一遍全篇逐字节比较

跨分块的 `flat_map().eq()`（单字节迭代器，10⁷ 次）走 `history.rs` 两个组合收尾点，每次中文输入提交多一遍全篇比较。语义修正是对的（旧 `zip` 版依赖分块边界，同正文不同分块会判「不等」，noop 组永不折叠），但成本落在 `buffer.clone()` 之上且在前台线程。修法：按 (块下标, 块内偏移) 双游标逐段 `as_bytes()` 比（每块一次 memcmp，语义仍与分块边界无关），或先比 `byte_len`。置信度 medium。
