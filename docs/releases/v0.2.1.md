# v0.2.1

本版更换搜索的匹配引擎：手写的大小写折叠、逐行喂入与偏移记账全部交给 ripgrep 的本体库（`grep-searcher` + `grep-regex` + `grep-matcher`，进程内调用，不启动 `rg` 子进程），并把同一个查询在结果列表、正文高亮、上/下一个跳转、全部替换四条路径上的四次独立计算收敛成**一张按缓冲区缓存的命中表**。对用户的直接结果是——正则模式可以跨行；写错的模式会给出引擎的原始诊断而不是静默搜出另一回事；跨块与跨行命中不再出现「列表说有、正文不画、点进去落错位置、全部替换偷偷少换」；10 MiB 文档的全篇扫描从五十余毫秒降到毫秒级，循环跳转的按键成本下降两个数量级以上。

## ✨ 新增

- **正则模式支持跨行**：`\n`、`[\s\S]`、`(?s)` 都能跨过行界，文档范围与工作区范围两侧同开。`.` 依 ripgrep 的默认**不跨行**——这一条写在 `.*` 按钮的悬停说明里（「正则可跨行：写 \n 或 [\s\S]；`.` 默认不跨行，加 (?s) 才行」），避免「开了跨行就什么都能跨」的直觉。
- **坏模式给出真诊断**：正则编译失败时，搜索框下方一行显示引擎的原始诊断（含指出出错列的 `^`，整行截断、悬停看全文），并**停止搜索**，不再把写错的模式当字面量搜出误导性的结果。
- **四处同源**：结果列表、正文高亮、`F3`/`F4` 落点、全部替换读同一张命中表，缓存键为「缓冲区身份 + 缓冲区修订 + 查询 + 四个开关」，任一变了才重算。跳转改为在表上取索引，与文档大小无关。
- **跨块命中全部打通**：命中跨过两个内容块时，高亮按块切段（此前要求「被某一块整条包住」，于是跨块命中一根都不画）；折叠章节按命中的**两端**展开（此前只看起点，尾部章节留在折叠里）；源码模式给出真正的跨块选区（此前被钳在起点所在分块，且端点换算存在下溢）；全部替换按字节写回真替换（此前静默跳过并少报计数）。
- **工作区命中按位置对位**：结果行的「第 k 个含命中起点的行」定义与文档范围统一到同一张表；跨行命中点进去选中整段而不是第一行。
- **非 UTF-8 笔记可搜正文**：工作区内容搜索的解码口径并进打开文档用的那一份实现（UTF-8 优先、GB18030 回退、最后才 lossy）。此前 `String::from_utf8` 一失败就整个文件跳过内容搜索，中文 Windows 上的 GBK/GB18030 笔记永远搜不到正文。
- **大小写不敏感按 Unicode 折叠**：中文、带音标拉丁字母与 `İ`/`ı` 一类非 ASCII 也参与折叠（`İ` 现在能配 `i`）。

## ⚡ 性能

以下两条口径分别注明构建档位，release 数字来自换引擎前的对照探针，debug 数字来自 `cargo test` 档位下的性能闸门（`tests/search_perf.rs`，10 MiB 中英混合夹具）。

release 探针，10 MiB 文档一次全篇扫描：

| 模式 | 换引擎前 | 换引擎后 |
| :--- | :--- | :--- |
| 中文单字 | 54.1 ms | 2.1 ms |
| 中文词 | 48.9 ms | 1.5 ms |
| ASCII 不区分大小写 | 14.5 ms | 9.6 ms |
| ASCII 区分大小写 | 8.5 ms | 2.6 ms |
| 正则 | 6.7 ms | 5.6 ms |
| 单词边界 | 7.2 ms | **7.5 ms（退步 4%）** |

单次循环跳转（同文档，20 处命中）：中文 61.0 ms → 0.006 ms，ASCII 9.50 ms → 0.076 ms，需要回绕时 12.88 ms → 0.079 ms。旧实现每次按键都把整篇重扫一遍、把所有区间收进一个 `Vec` 再线性找下一个，回绕等于扫两遍。

debug 档位，10 MiB 文档 / 常用词 53 227 处命中：整篇扫描 50–175 ms；连按「下一个」的首次按键仍需铺一遍全文高亮（9.95 s，见「已知限制」），**之后每次 125 ms**。这一段两次实测驱动的修复把按键成本从 26.3 s 降到 125 ms：先消掉「对每根块重筛整张命中表」的 O(块数 × 命中数)（26.3 s → 9.95 s），再把循环跳转改成只挪活动命中的标记、不重铺其余块（9.95 s → 125 ms）。1 MiB / 5 322 处命中为 317 ms → 18.8 ms。

- **工作区内容缓存的驱逐改为 O(1)**：此前每次插入都要把整表求和一遍、超预算再线性找最久未用，2000 文件 / 约 140 MB 语料顶穿 128 MB 预算后每插一条都走一遍全表，表现为热跑稳定比冷跑慢 45%。改为总字节即时记账 + 插入序队列后，同进程 A/B（1 200 次插入）23.6 ms → 2.5 ms。
- 单词边界模式在全篇扫描上慢 4%（引擎把 `\b` 编进模式，比「廉价字面量扫 + 事后过滤」重）。这一条不粉饰，性能闸门的阈值按最慢形态设定。

## 🐛 修复

- 正则模式下「全词匹配」开关被完全忽略（提前返回），开着 `ab` 仍把 `NeedleHere` 判为命中。现由引擎的 `\b` 负责。
- 非法正则被 `.build().ok()` 静默退化成字面量搜索，用户以为在跑正则。
- 带 `\n` 的模式必然空手：搜索逐行喂，跨行在结构上不可能。
- 文档范围结果行的序号重复：同一行第二个命中取的是已自增的序号，于是它与下一根含词行的第一个命中拿到同一个 ordinal。
- 跨块命中的高亮一根都不画、折叠章节的尾部不展开、源码模式选区被钳在起点分块、`replace_all` 静默跳过跨块命中且计数虚报。
- 零宽命中越界：`grep-regex` 的 `find_iter` 在零宽命中上按**字节**步进，会吐出落在「中」「文」这类三字节字符内部的区间（`regex` crate 按字符步进所以没有）。这类区间流进替换路径就是 panic，现在在引擎出口统一按字符边界过滤。
- 多行模式下行尾符被无条件剥离，导致 `needle\n` 一类模式 0 命中、`[\s\S]+` 少报一处。现在只在行式档位剥离。
- 相邻重复命中被上报两次（`x*` 在 `ab\nab\n` 上给出 8 条含重复 `3..3`），两个 sink 出口各加相邻去重。
- 命中表跨文档串用：两份从未编辑过的文档修订号都是 0，在 A 搜完切到 B 搜同一个词会把 A 的区间当成 B 的，现象是跳转后高亮整体消失。缓存键补入缓冲区身份号。
- 命中跨行时结果行的预览与行内区间算错（行尾从命中**终点**推行，把整段吞进一行）；改从命中起点推。
- `replace_all` 走缓冲区写回那一路只准备未提交撤销快照，一次撤销什么都不退回。
- 跳转把焦点从搜索框抢进正文后，继续敲字会直接改写文档；表格单元格内的命中点了没反应（滚动锚点落在不注册进块树的 cell 上）。

## ⚠️ 语义变化

- 非法正则从「静默按字面量搜」改为「显示诊断并停止搜索」：结果列表会变空，这是预期行为。
- 大小写不敏感的折叠从 ASCII + 逐字符比较改为 Unicode 折叠，命中集合会变化（多出 `İ`/`ı` 一类）。
- 正则模式下同时开启「全词」时命中集合会**变小**（此前该开关被忽略，多算的那些现在不算了）。
- 「全部替换」的计数在含跨块命中的文档上会比旧版**更大**（旧版静默跳过，新版真替换）。
- 正则与模糊同时开启时仍按**正则优先**，模糊开关被忽略（在册缺陷 #2，未修）。
- 工作区结果行的序号定义改为「第 k 个含命中**起点**的行」。对不跨行的查询与旧定义逐位相同（有一条逐位对照的测试钉住），只有真跨行命中走出新语义。

## 🧪 测试与可靠性

- 测试数 1298 → **1393 通过 / 0 失败 / 6 ignored**，编译零警告；搜索链路用例 135 条。
- 阶段 0 先建立 32 条行为快照（其中 6 条 `defect_` 前缀钉住当时实测到的真实缺陷），换引擎后仅 3 条按修复后的期望改写，其余一条未动期望值——任何行为漂移都只能是被点名、被解释的改动。
- 新旧引擎对照：10 份语料 × 5–7 种模式 × 23 个查询共 800 余组，逐一断言命中区间集合**逐位相同**；参照实现是退役手写层算法的誊本（留在测试里，不是转调生产代码的门面）。
- 一处对照测试被掏空的问题被记录在案：手写层从生产代码删除后，对照测试的参照已退化成「引擎和引擎比」，测试仍全绿但不再比任何东西。补回参照实现后重新验证其杀伤力。
- 随机一致性属性测试：随机生成 24 篇 markdown × 随机开关，逐轮断言四处同源（列表 == 表、高亮段数 == 命中数、`F3` 走一圈的落点序列 == 表、替换计数 == 命中数且替换后重扫归零）。
- 三道性能闸门进测试套：10 MiB 扫描预算、70 次跳转命中表重扫必须为 0、循环跳转不得重铺其余块（单块映射重建次数不随命中数长）。

## ⚠️ 已知限制

- **修改查询那一次的高亮同步仍是全量**，代价 O(有命中的块数)。10 MiB 文档搜索一个常用词（53 227 处命中）实测 9.95 秒，而搜索框每敲一个字都要付一次。该形状在换引擎前就存在，不是本版引入的退步；修法是高亮只按可视窗口铺开。
- **GB18030 文件仍无法在编辑器中打开**：工作区标签的文本嗅探只看头 8 KiB 能否按 UTF-8 解释。本版只统一了搜索侧的解码口径，搜索已能命中其正文。
- 多文件工作区扫描受 I/O 主导，换引擎只有 1.08–1.17 倍，与预期一致。
- 大文档的结果列表与正文高亮仍按全文档铺开，未按视口裁剪。
