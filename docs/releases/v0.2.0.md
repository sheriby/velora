# v0.2.0

本版更换文档内容的存储与写盘模型：文本以内存缓冲区为唯一事实源（严格镜像磁盘文件，仅在保存时写盘），块结构是其上指向字节区间的投影；编辑按区间写回缓冲区，保存输出缓冲区按文件形状编码的结果。对用户的直接结果是——未编辑的文件保存后字节完全不变，编辑仅改写被修改位置所涉及的字节；大文档的单次按键成本下降一至两个数量级。原先分散在打开、输入与保存路径上的隐式规范化已全部移除，集中到显式命令「格式化文档」。

## ✨ 新增

- **保存的内容保真**：未编辑的文件保存后字节完全不变，包括末行换行的有无、CRLF 与混合行尾、UTF-8 BOM、GB18030 编码。Markdown 的记号写法与手工排版作为文档内容的一部分予以保留，不再在写盘时被规范化：强调标记 `__…__` 与 `~~…~~` 不改为 `**…**`；有序列表记号 `1)` 不改为 `1.`；列表项符号 `-`、`*`、`+` 与任务复选框写法保持原样；分隔线 `***`、`___` 不改为 `---`；标注头 `[!note]` 不改为 `[!NOTE]`；引用记号后无空格的形式（`>正文`）不补空格；代码围栏 `~~~~` 不改为 ```` ``` ````；字面反斜杠（`\*`、`\_`、`C:\Users`）不再被重新解释为转义语法；表格的列宽填充与 `|:-------|` 对齐写法不变；Setext 标题的下划线形式保留；缩进式代码块不被改写为带围栏的形式；硬换行结尾的反斜杠不被转义为 `\\`。
- **「格式化文档」命令**（菜单与命令面板，⌘⇧L / Ctrl+Shift+L）：上述规范化操作集中于此，一次完成 Setext→ATX、强调标记归一、列表记号归一、表格列宽重排与根块间分隔空行的补全。实现为三步——清除模型中记录的原始写法、按默认写法序列化并与缓冲区比对、以最小差异写回后从缓冲区重建投影；比对结果相同时不产生任何副作用（不改写字节、不置脏、不生成空撤销组）。源码与代码文档不改动任何字节。格式化后撤销并重新输入，不会恢复出已被清除的旧记号数据。
- **结构性编辑改为按字节区间写回**：回车拆块、退格合块与删除空行、Tab / Shift-Tab 的缩进、提级与降级、任务复选框勾选、Setext 下划线成标题、表格分隔行成表与续行、表格八条命令（增行、删行、列对齐、增列、删列、移动行、移动列、删除表头）、引用与标注内拆块、空标注降级为引用、嵌套列表项降级为子段落、整表删除、多行粘贴、跨块选区的删除与替换、图片粘贴。此前这些操作在改动块树后将整篇文档重新序列化并覆盖缓冲区，会同时改写未参与操作的内容。
- **源码模式（Markdown 源码视图、代码与纯文本文件）直接编辑缓冲区**：移除按键路径上的整篇文本重拼、整篇比对与整篇写回。同时完成该视图的排版修订：源码分块统一使用等宽字体与代码字号（行号与正文字体一致）；Markdown 源码块接入既有 tree-sitter 高亮管线，标题、围栏、行内代码与强调记号按代码文件同一套主题色着色；行号栏宽度按全文档总行数统一计算，上下分段右对齐，左侧留白由 48px 减至 24px；行号与正文间距由 12px 增至 16px；取消聚焦块的全屏底色；视图切换图标仅在存在渲染视图的 Markdown 文档上显示。
- **坐标口径统一到文件**：编辑器行号、状态栏行列号、搜索命中、大纲跳转与跨块复制均使用缓冲区坐标，即文件自身的字节位置。附带修正：空表格单元格此前无法建立位置映射，光标位于其中时粘贴、跳转与行列号只能退回默认位置；引用与列表中的表格改为按结构量取单元格区间，此前以序列化文本回查原文的口径在表头含转义竖线时会导致整张表无映射。
- **脚注序号同步回填**：`[^1]` 渲染为上标序号后，在其前后输入或删除字符不再退回源码形式（此前会瞬时增加三个可见字节，光标位置与字数统计随之失准）。
- **当前搜索命中的高亮色**改为橙色（`#ff9500`，不透明度 70%），与未选中命中的浅黄色区分。此前该色绑定主题选区色，在 Forest 主题下为淡绿，与正文无法区分。
- **大文件的点击落位**：源码模式按 512 行分块后，位于首块之外的搜索命中、大纲与 `[TOC]` 跳转让选区被限制在首块末尾；后台分块尚未完成时首次点击无响应，需再次点击。现按落点解析所属投影块，并在跳转前完成待建分块的实例化。

## ⚡ 性能

以下数据于本机实测，dev 无优化构建、性能夹具就位（`node scripts/generate-fixtures.mjs fixtures/perf`），采集命令 `cargo test probe_attribute_ten_mib -- --ignored --nocapture`。

| 场景 | 单次按键耗时 | 整篇序列化 / 整篇映射重建 / 大纲整篇重扫 |
| :--- | :--- | :--- |
| 10 MiB Markdown | 103–105 ms（首帧 150 ms） | 0 / 0 / 0 |
| 10 MiB 代码文档 | 21.5–23.1 ms | 0 / 0 / 0 |
| 10 MiB Markdown，大纲侧栏展开（53,227 条标题） | 正文中 201–203 ms，标题中 226–319 ms | 0 / 0 / 0 |

对照数据：更换模型之前，同一文档的单次按键为 13 秒量级（每次按键复制整篇文本并序列化比对）；本次重构过程中测得的最差记录为大纲展开时 2.3–2.6 秒。

- 1 MiB Markdown 单次按键 280 ms → 51 ms；1 MiB 文档切换至源码视图后单次按键 1.99 s → 141 ms；1 MiB 代码文档 26 ms。
- **撤销栈改为存储增量**：200 步操作 ≤ 64 KiB（此前每步保存一份全文快照，10 MiB 文档最坏情况约 2 GB）。1300 字段落的一次拆块由记录 2400 字节降至 0。
- 逐项定位并消除的线性成本：大纲「整篇按行重扫」585,499 行 → 0 行（改为按根块摘要增量重建，并将围栏状态作为缓存键的一部分）；行号换算的正文读取量 196,119 字节 → 0 字节（每个文本块维护自身换行偏移表，分块仅平移两张表）；行计划重建 121 ms → 41 ms → 输入时 0 次（缓存键由文档修订号改为行元数据版本）；编辑后的源码区间平移 57 ms → 约 1 ms（区间数据由块实体上移至块树表格）；单次大纲跳转减少 4 次整篇映射重建；滚动跟随减少一次全文复制与一次全文换行扫描；5.3 万行大纲面板改为按视口开窗渲染；引用内一次回车由「2 次整篇序列化 + 62 个根块实体全部重建」降为「0 次 + 1 个根块」。
- 导出、状态栏行列号与引用定义解析不再重拼整篇文档；10 MiB 文档不再常驻两份全文副本（稳定快照与文内查找快照已移除）；侧栏收起时不再每帧重算大纲。

## 🐛 修复

- **崩溃**：含中文或 Emoji 的 `.py` / `.txt` 文件在输入时 panic（以 Markdown 围栏口径计算代码文档行字节长度，切片位置落入多字节字符内部）；源码映射切片起点落在多字节字符内部时在非展开执行上下文中终止进程；撤销表格「移动一行」时，等长但内容不同的文本比较触发 panic。
- **输入落点错误**（界面显示正确、写入位置错误）：四空格或制表符缩进的嵌套列表中，字符被写入父列表项所在行（制表符同时被替换为两个空格）；列表项内四空格缩进的代码围栏，字符写入同根列表的相邻行；缩进式代码块中字符落入相邻行；引用续行使用 `>正文` 形式时，字符落入记号与内容之间；四空格缩进的续段落，字符落入缩进空白中；列表项空行之后的续段落，字符落入空行并丢失缩进；在标题起始处输入时字符被插入到 `#` 之前（界面显示为标题，磁盘上为段落，重新打开即为段落）；硬换行的续行输入使文件中的 `\` 被改写为 `\\`，并连带偏移后续所有行的落点。
- **字节损坏**：向以 LF 为规范形式的缓冲区粘贴 CRLF 文本，保存时按文件形状再次升格为 `\r\r\n`，文件出现多余空行；同时该文件的版本号与实际内容不一致，被误判为外部修改并停止自动保存。粘贴入口统一归一化，编码函数补充末道校验。
- **绕过统一写入口的路径**：自动保存与关闭时的批量保存写入 LF / UTF-8 文本，CRLF 与 GB18030 文档经这两条路径被转换；外部修改触发重载后未重新绑定文件来源，重载后的首次保存对整个文件重新编码。
- **撤销**：输入法逐键组合的后续更新同样写入缓冲区，但仅在组合开始时建立撤销组，增量未被记录，撤销后残留中间状态；直接修改模型的路径（重命名、程序化编辑）在 `Changed` 事件上漏记撤销增量。
- **写法被改写**：除上述落位问题外，还包括回车拆块时改写同块内未涉及的定界符、整块写回时统一引用前缀、跨块复制—粘贴使 Setext 标题降级。
- **快照与标签**：会话标签与恢复快照保存的是整篇序列化结果，恢复出的内容与用户打开的文件不一致，且该差异无法通过撤销恢复；仅行尾不同的磁盘文件被误判为外部修改，导致每次文件监听事件都重新导入整篇；拖拽替换前的另存直接写入序列化结果且未使用原子写。
- **定位与高亮**：搜索高亮自转义位置起整体偏移一个字符（序列化器为字面 `~`、`*`、`_` 补写反斜杠，块文本比缓冲区多出这些字节；命中「含测试」时高亮落在「含」上）；模糊匹配的区间起点未固定在查询首字符处；全文替换的替换计数虚报；图片与链接注册表在写回之前刷新，修改 `[asset]:` 地址后图片仍指向旧地址；表格单元格写回传入区间平移的起点为编辑后坐标，向末位单元格粘贴较长内容时后续根块区间整批失效，下一次写回落入错误字节。
- **显示形态**：缩进式代码块将块后的分隔空行计入内容，渲染多出空档；在块首输入 `# `、`- `、`> ` 使块类型就地变化后，行间距沿用段落档直至下一次结构变化；`[TOC]` 在后台分块期间保持不完整，直到首次编辑才补全；大纲出现错误条目（表格行之后的 `--` 被判定为 Setext 标题、YAML 中的 `#` 被判定为标题）；Markdown 源码视图铺满聚焦块底色；源码分块行号栏上下两段未对齐。
- **其他**：图片粘贴未写入文档时遗留已生成的资源文件；另存对话框打开期间缓冲区变化，导致写入后的文件被误判为外部修改；区域重解析的探测窗口宽度等于本段行数，探测分支从未执行，结构外扩时缺少回退判定。

## ⚠️ 破坏性变更

- **保存不再对文档执行规范化。** 这是本版需要用户调整预期的唯一变更。此前保存会补全块间空行、重排表格列宽、将 Setext 标题转换为 ATX、统一记号写法为规范形式，并可能丢失 CRLF、末行换行或将非 UTF-8 转为 UTF-8。现在未编辑的文件保存后字节不变，编辑仅改写涉及区间。原先依赖「保存即整理」的工作流请改用「格式化文档」（⌘⇧L / Ctrl+Shift+L）。
- **混合行尾文件**（同一文件内同时存在 CRLF 与裸 LF）不存在单一可记录的行尾形状：未编辑时按原始字节回写，发生编辑后按 LF 落盘，不会将 LF 行升格为 CRLF。
- 非 UTF-8（GB18030）文件的**编码变更提示**未包含在本版：此类文件现在以字节保真方式打开、编辑并写回原编码，但不提供转换为 UTF-8 的询问。

## 📝 其他

- 测试 **1298 通过 / 0 失败 / 6 忽略**（性能夹具就位时约 27 秒）。本版新增的验收以字节断言为主：27 个文档形状 × 三个维度（未编辑保存、编辑后保存、拆块后保存）的往返保真矩阵，并扩展到 UTF-8 BOM、GB18030 与混合行尾；11 个嵌套形状与 4 种缩进方式的落点断言；「一次真实编辑序列中整篇重新序列化必须为 0 次」的闸门测试（其兜底白名单当前为空，只允许缩减）；「按解析期记录换算失败的形状数」闸门在会话全流程为 0。
- 文档：`docs/architecture/editor-core.md` 按新模型重写；关键不变式扩充至 23 条，本版新增的内容为「源码文档的块是缓冲区的一段切片」「规范化只出现在显式的格式化命令中」「读侧派生视图只重算被改动字节所在的块（三个失效信号）」「记号宽度是解析期记录的数据，重新分配区间时必须使其失效」「按行分块的派生扫描须将跨段状态计入缓存键」。
- 移除的旧机制：以整篇序列化结果作为文档内容来源的路径（`serialized_document_text`、`raw_source_text`、`last_stable_source_text`、`document_search_source`），以及缓冲区内的锚点层（块区间直接以字节偏移记录）。
- 尚未完成的部分：源码与代码文档的结构命令（回车拆块、删除块）仍走整篇重投影，这是该路径上最后一处随文档长度增长的按键成本；按行窗口渲染（10 MiB 纯文本的流畅滚动）与大纲树的增量拼装各自为独立工作项；表格单元格的搜索高亮在含行内数学、上下标、内嵌图片的单元格、长块兜底路径以及 HTML `<table>` 上仍未实现；上游依赖 `block v0.1.6` 与 `proc-macro-error2 v2.0.1` 的 future-incompat 提示仍存在。
