# Velora dev 分支迭代路线图（对照 Typora / Obsidian）

日期：2026-09-27
状态：执行中（dev 分支分段提交，完成后由用户 review 合入 main）

## 目标

- 可用性 / 可靠性 / 交互性全面强于 Typora 与 Obsidian 的日常写作场景。
- 代码保持高性能（长文档流畅编辑）、可维护（模块边界清晰、有测试）、可扩展（主题 / i18n / 配置驱动）。

## 现状盘点（已具备能力）

- 所见即所得 Markdown 渲染（块级 + 行内：标题/列表/表格/代码块/行内代码/数学/mermaid/脚注/callout/任务列表/图片）。
- 工作区侧栏：文件树（新建/重命名/删除/右键菜单）、VS Code 风格搜索（大小写/全词/正则/模糊、替换、工作区范围替换）、大纲（点击跳转、默认展开 H3）。
- 文档标签页：合并进标题栏、逐标签关闭、右键批量关闭；「打开最近」合并文件与文件夹；文件夹选择对话框（替换当前工作区 / 新窗口）。
- 源码 / 渲染双模式；专注模式、打字机模式；自动保存 + 崩溃恢复；外部修改检测。
- 导出 HTML / PDF；主题（深/浅/系统）；中英文 i18n；快捷键自定义；状态栏（字数、选中统计、行数）。
- 文本文件按内容嗅探打开；二进制文件占位提示；窗口标题栏自绘。

## 与 Typora / Obsidian 的差距（roadmap 依据）

Typora 强在「细节打磨」：列表续写、智能标点、粘贴转换、TOC、导出矩阵、主题生态。
Obsidian 强在「知识管理」：命令面板、快速切换、双链、标签、反链、图谱、日常笔记。
Velora 当前两侧都缺一批高频能力，以下按「P0 日常刚需 → P1 体验增强 → P2 进阶」组织。

## 执行顺序

1. A1 → A2 → A4（启动体验三件套，用户点名的欢迎页与窗口记忆优先）。
2. B1 → B2 → E1 → E4 → E5（编辑与导航高频项）。
3. C1 → C5 → C3/C4（知识结构）。
4. D1 → D3 → D4（文件可靠性）。
5. G1 → G3 → G2（可靠性）。
6. 其余按 P1 → P2 推进，每项完成即测试 + 提交。

## 验收与提交约定

- 每项独立提交，标题格式 `feat(scope): 描述` 或 `fix(scope): 描述`。
- 涉及行为的改动补 gpui test 或单测；UI 改动以截图/验收记录佐证。
- 全部完成后在本文档更新各项状态，由用户 review 后合入 main。
