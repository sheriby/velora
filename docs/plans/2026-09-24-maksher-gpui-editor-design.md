# maksher 原生编辑器设计

日期：2026-09-24
状态：首版核心功能已实现，设备验收中

## 目标与边界

maksher 是以长篇 Markdown 写作为主的桌面编辑器。首版先发布 macOS；Windows 在下一版正式发布，首版只要求能构建内部安装包。默认使用富文本编辑，另有 Markdown 源码模式；在单根文件夹工作区中浏览 Markdown 和代码文件。初版不做 AI、Linux、终端、Git 集成、公式或 Mermaid。

首版功能包括文件树、多标签、最近工作区、文件名搜索、文内查找、标题大纲、文件和文件夹的新建/重命名/移动/删除、代码编辑与语法高亮、图片复制到工作区目录并使用相对路径、自动保存、撤销与意外退出恢复。当前实现包含这些功能，并采用 Fluent 中性色、系统浅/深主题和紧凑工作区工具栏；可打开 docs/design/界面原型.html 查看布局参考。

## 当前实施状态

- macOS GPUI 应用可用 fastdev 启动；内部分发 .app 与 .pkg 已可构建。
- Windows x64 GNU 目标可交叉编译，NSIS 内部安装器已构建；尚未进行 Windows 实机运行验收。
- 文件树、同窗代码编辑标签、多标签、最近工作区、搜索和文件操作已实现。
- 代码浏览支持常见语言语法高亮；SQL、Swift、Kotlin、XML 等无高亮语法包的文件仍可在同窗标签中按纯文本编辑。
- 图片粘贴/拖入使用工作区资源目录与相对路径；移动单个 Markdown 文件时更新内联及引用式图片路径。
- 自动保存、逐标签恢复快照和外部修改冲突保护已实现。
- 可界定的 `:::` 扩展块作为可编辑原文保存；未闭合指令和 `!!!`/`???` 提示块触发源码模式，并在编辑区说明原因。
- Fluent 中性色、浅/深主题和跟随系统外观已落实到 GPUI。
- 中文组合输入有自动化模拟测试；真实 macOS 拼音候选框与连续输入仍需手工验收。

逐项命令与测试证据见 [首版开发验证记录](../验收记录/2026-09-25-首版开发验证.md)。

## 方案选择

选择 **Rust + GPUI 新应用结构，选择性抽取 Velotype 编辑实现**。maksher 自己管理窗口、工作区、标签、文件操作、保存和恢复；从 Velotype 固定提交一次性抽取 Markdown 解析/序列化、块编辑、选择、历史和渲染所需代码。之后只按需要手动移植上游修复，不建立持续同步机制。

考虑过另外两条路线：

1. 完整 fork Velotype：能最快继承现有原生编辑器，但也会继承应用级窗口、菜单和工作区结构，改造边界不清。
2. 从头实现原生编辑器，只借鉴思路：结构最自由，但富文本、Markdown 往返和输入法都要重做，交付风险最高。

Velotype 的本地基线固定为提交 `ed65977be94f2f2703037fcb8b6cbab2e7579571`。它使用 Rust + GPUI，已有富文本与源码模式、块模型、图片粘贴、主题和大文档可视区域裁剪。其编辑核心与应用层紧密相连：`Editor` 同时持有文档、焦点、滚动、菜单及窗口状态，`DocumentTree` 直接依赖 `Context<Editor>`。抽取因此是需要验证的重构，不能把复制若干文件视为完成。[Velotype 编辑器](https://github.com/manyougz/velotype/blob/ed65977be94f2f2703037fcb8b6cbab2e7579571/src/editor/mod.rs)、[DocumentTree](https://github.com/manyougz/velotype/blob/ed65977be94f2f2703037fcb8b6cbab2e7579571/src/editor/tree.rs)。

## 架构与数据流

- **编辑部件**：内部 GPUI 组件负责 Markdown 富文本/源码模式、块结构、选择、撤销及序列化，向应用层暴露打开、内容变更、焦点、保存内容和错误状态。它不持有工作区根目录、文件树、全局菜单或磁盘保存策略。
- **应用窗口**：一个窗口对应一个根文件夹。每个标签缓存各自的文本和脏状态；窗口负责文件树、标题大纲、搜索、主题和活动标签切换。
- **代码编辑**：代码文件使用同一窗口的标签和现有原生文本输入能力，以源码模式编辑；支持输入法、语法高亮、撤销和保存。文件树按需读取，避免启动时递归渲染整个工作区。
- **文件服务**：应用层读取文件并向编辑部件交付文本。编辑后先保存恢复草稿，再安全写回原文件；外部修改导致版本冲突时暂停覆盖并提示。移动或重命名文件后，同步标签路径及受影响的相对图片引用。
- **Markdown 安全性**：已支持结构保存内容和排版语义，允许规范化标记写法。可识别但不支持的语法保留可编辑原文；无法安全转换的文件进入源码模式。任意未知插件语法无法保证被自动识别，产品文档必须如实说明边界。
- **输入法**：中文拼音组合输入期间不触发保存或拆分撤销记录；候选词确认后再提交编辑结果。macOS 真实输入操作是首版验收项。

## 可行性关口

当前开发阶段先实现可用的 maksher 编辑窗口，完成打开 Markdown、富文本输入、中文拼音、撤销、保存和源码回退。开发验证使用 debug 构建，不做 release 编译。核心功能可用后，再对未修改的 Velotype 和 maksher 做同机性能测量；若抽取必须长期保留大部分 Velotype 应用层，或性能明显退化，再重议复用边界。

基准机为当前 Mac mini M4、16 GB。实际生产构建使用固定的 1 MB 和 10 MB Markdown 样本，测从进程启动到可输入、从打开文件到可输入，以及长文输入延迟。maksher 目标为：冷启动 ≤1 秒；打开 1 MB ≤1 秒；打开 10 MB ≤5 秒；输入响应 p95 ≤50 毫秒。Velotype 仓库中的局部渲染基准只能帮助定位瓶颈，不能替代整机测量。

## 验收与风险

- 中文拼音验收覆盖候选词位置、组合输入、跨块编辑、撤销、保存和重开，均不能丢字。Velotype 的路线图仍将更完整的 IME 行为列为待办，所以它是早期关口。
- Markdown 固定样本覆盖受支持语法的读取、编辑、保存、重开、语义往返与不支持语法回退；文件测试覆盖外部修改冲突、原子写入和意外退出恢复。
- macOS 在真实安装包中验收界面原型、工作区、代码编辑、主题及性能。Windows 首版只构建内部安装包，不宣称运行体验已验证。
- macOS `.app` 与 `.pkg` 可由 fastdev 脚本生成；Windows x64 使用 GNU 交叉编译和 NSIS 构建内部安装包。Windows 实机运行仍需后续验收。
- Velotype 标为 Apache-2.0。抽取时保留对应许可和版权声明，记录固定来源提交与修改范围；maksher 使用自己的名称与视觉资产。分发前核对依赖及 NOTICE 要求。参见 [Apache License 2.0](https://www.apache.org/licenses/LICENSE-2.0)。
- 先前未提交的 Tauri 脚手架已按用户要求删除；后续只按本 GPUI 设计推进。
